03

변수와 데이터 입력

잔액은 입금과 출금에 따라 계속 바뀝니다. 바뀌는 값을 담아 두는 그릇이 변수이고, 그 그릇의 크기와 모양을 정하는 것이 자료형입니다. 이 장에서는 변수가 메모리에서 실제로 어떤 모습인지 그림으로 확인하고, 사용자에게서 값을 안전하게 입력받는 방법까지 익힙니다. scanf에 왜 &를 붙이는지, 잘못된 입력이 들어오면 왜 프로그램이 무한 반복에 빠지는지 끝까지 파고듭니다.

이 장에서 배울 것

  • 변수의 선언, 초기화, 대입을 구분하고 메모리 그림으로 설명할 수 있습니다.
  • 정수형·실수형·문자형 자료형의 크기와 표현 범위, signed와 unsigned의 차이를 압니다.
  • sizeof로 자료형 크기를 확인하고, 초기화하지 않은 변수(쓰레기값)의 위험을 이해합니다.
  • const와 식별자 이름 규칙, 실무 명명 관례를 익힙니다.
  • scanf의 동작 원리와 &가 필요한 이유, 서식 지정자를 정확히 맞추는 법을 압니다.
  • scanf의 반환값 검사, 입력 버퍼, 잘못된 입력 처리 방법을 익힙니다.

03-1변수

변수는 왜 필요한가

2장에서는 printf("잔액: %d원\n", 15000);처럼 값을 코드에 직접 적었습니다. 하지만 실제 프로그램에서 잔액은 고객마다, 거래마다 다릅니다. 입금이 들어오면 늘고 출금하면 줄어듭니다. 이렇게 실행 중에 바뀌는 값을 저장해 두는 메모리 공간에 이름을 붙인 것이 변수(variable)입니다.

1장에서 메모리는 주소가 붙은 바이트 칸의 연속이라고 했습니다. 이론적으로는 "0x7ffd1000번지부터 4바이트에 잔액을 넣어라"라고 할 수도 있지만, 사람이 주소를 일일이 관리하는 것은 불가능에 가깝습니다. 그래서 C는 balance 같은 이름을 붙이면 컴파일러가 알아서 메모리 위치를 정하고, 이후 그 이름을 쓸 때마다 해당 주소의 값을 읽고 쓰는 기계어를 만들어 줍니다.

변수의 4요소

모든 변수는 이름, 자료형, 값, 주소를 가집니다. 자료형은 "몇 바이트를 차지하고, 그 비트들을 어떻게 해석할지"를 정합니다. 같은 4바이트 0x41200000도 int로 읽으면 1092616192이고 float로 읽으면 10.0입니다. 메모리에는 비트만 있고 의미는 자료형이 부여한다는 사실이 C를 이해하는 핵심입니다.

변수 선언, 초기화, 대입

  • 선언(declaration): 자료형 이름; 형태로 "이런 이름의 이런 자료형 변수를 쓰겠다"고 알립니다. 지역 변수는 이때 메모리(스택)에 공간이 마련됩니다.
  • 초기화(initialization): 선언하면서 첫 값을 주는 것입니다. int balance = 15000;
  • 대입(assignment): 이미 존재하는 변수에 새 값을 넣는 것입니다. =는 수학의 '같다'가 아니라 "오른쪽 값을 왼쪽 공간에 저장하라"는 명령입니다.

왜 그럴까? — balance = balance + deposit은 수학적으로 말이 안 되는데?

수학에서 x = x + 1은 해가 없는 식이지만, C의 =는 방정식이 아니라 대입 연산자입니다. CPU는 이 문장을 다음 순서로 실행합니다. (1) balance의 메모리에서 현재 값(15000)을 레지스터로 읽는다, (2) deposit의 값(30000)을 읽어 더한다, (3) fee(500)를 뺀다, (4) 결과 44500을 balance의 메모리에 쓴다. 오른쪽이 먼저 완전히 계산된 뒤 왼쪽에 저장되므로 자기 자신을 사용해도 문제가 없습니다. 이 때문에 = 왼쪽에는 반드시 값을 저장할 수 있는 공간(변수 같은 lvalue)이 와야 하며, 15000 = balance;는 오류입니다.

여기서 잠깐 — 선언 위치: C89와 C99

C89에서는 블록의 맨 앞, 즉 실행 문장들보다 먼저 모든 변수를 선언해야 했습니다. C99부터는 블록 중간 어디서든 선언할 수 있고, for (int i = 0; ...)처럼 반복문 안에서도 선언할 수 있습니다. 오래된 금융권 소스를 보면 함수 시작 부분에 수십 개의 변수가 몰려 선언된 C89 스타일이 흔합니다. 새 코드에서는 변수를 처음 쓰는 곳 가까이에서 선언하고 바로 초기화하는 것이 실수를 줄입니다.

왜 그럴까? — 범위는 왜 -128 ~ 127처럼 음수 쪽이 하나 더 클까?

n비트로 만들 수 있는 비트 패턴은 2n가지입니다. 8비트면 256가지입니다. 부호 없는 경우는 0~255를 모두 양수로 씁니다. 부호 있는 정수는 현대 컴퓨터가 모두 2의 보수(two's complement) 방식으로 표현하며(C23부터는 표준이 2의 보수를 의무화), 맨 왼쪽 비트(최상위 비트)가 1이면 음수입니다. 0은 0000 0000 하나뿐이므로 양수 쪽에서 한 자리를 차지하고, 그 결과 음수 128개(-128~-1), 0 하나, 양수 127개(1~127)로 나뉩니다. 2의 보수는 덧셈 회로 하나로 뺄셈까지 처리할 수 있어서 하드웨어가 단순해진다는 큰 장점이 있습니다(20장에서 자세히 다룹니다).

signed와 unsigned, 그리고 오버플로

정수형 앞에 unsigned를 붙이면 음수를 표현하지 않는 대신 양수 범위가 두 배가 됩니다. signed는 부호 있음을 명시하며, int, short, long은 기본이 signed입니다. 단 char만은 signed인지 unsigned인지가 구현 정의입니다(x86 gcc는 signed, ARM 리눅스 gcc는 unsigned).

범위를 넘는 값을 만들면 어떻게 될까요? 여기서 signed와 unsigned가 결정적으로 다릅니다.

왜 그럴까? — signed 오버플로는 왜 UB일까?

C가 만들어질 당시에는 2의 보수 외에도 1의 보수, 부호-크기 방식 같은 다른 음수 표현을 쓰는 컴퓨터가 있었습니다. 방식마다 오버플로 결과가 달랐기 때문에 표준은 결과를 정하지 않았습니다. 오늘날 이 UB는 최적화의 근거로 쓰입니다. 예를 들어 컴파일러는 if (x + 1 > x)를 "signed 오버플로는 일어나지 않으므로 항상 참"이라 판단해 조건 검사 자체를 지워 버릴 수 있습니다. 그래서 "오버플로가 나면 음수가 되겠지"라고 기대하고 if (balance + amount < 0)으로 오버플로를 검사하는 코드는 최적화 옵션에 따라 검사가 사라질 수 있습니다.

이렇게 해결합니다 — 연산 전에 범위를 검사

더한 결과를 보고 판단하지 말고, 더하기 전에 여유 공간과 비교합니다. gcc/clang의 __builtin_add_overflow나 C23의 <stdckdint.h>도 쓸 수 있습니다.

자주 하는 실수 — 금액에 unsigned를 쓰면 안전할까?

"잔액은 음수가 될 수 없으니 unsigned로 하자"는 생각은 위험합니다. unsigned int balance = 1000; balance = balance - 3000;은 오류 없이 4294965296이라는 거대한 양수가 됩니다. 잔액 부족을 검사하는 balance - amount < 0은 unsigned에서는 항상 거짓이라 검사가 무력화됩니다. 금액은 signed 64비트(long long 또는 int64_t)로 다루고, 음수가 되면 안 되는 조건은 코드로 명시적으로 검사하는 것이 정석입니다.

은행 시스템에서는 — int로 충분할까?

int의 최대값은 약 21억 원입니다. 개인 계좌 잔액은 대부분 이 안에 들지만, 법인 계좌, 지점별 일일 합계, 은행 전체 총수신고처럼 집계 금액은 쉽게 수조 원을 넘습니다. 또 원금 × 이율(만분율)처럼 중간 계산 값은 최종 결과보다 훨씬 큽니다. 예를 들어 원금 3억 원 × 350bp = 1,050억으로 int를 넘습니다. 그래서 금융 프로그램의 금액 변수는 처음부터 long long(최대 약 922경)으로 선언하고, 고정 폭이 필요한 구조체(전문, 파일 레코드)에는 <stdint.h>의 int64_t를 씁니다. 이것은 코딩 표준으로 정해 두는 경우가 많습니다.

왜 그럴까? — float에 넣은 123456789가 왜 123456792가 될까?

float는 32비트 중 23비트(숨은 비트 포함 24비트)만 유효 숫자(가수)에 씁니다. 224 = 16,777,216을 넘는 정수는 모두 표현할 수 없고, 그 위로는 표현 가능한 수 사이의 간격이 2, 4, 8…로 벌어집니다. 1억 2천만 근처에서는 간격이 8이므로 123456789에 가장 가까운 표현 가능한 값 123456792로 저장됩니다. 마찬가지로 16777216 + 1 = 16777217은 표현할 수 없어 16777216으로 반올림됩니다. float로 금액을 다루면 1억 원대에서 이미 원 단위가 틀린다는 뜻입니다. double은 253(약 9천조)까지의 정수를 정확히 표현하지만, 0.1 같은 소수는 여전히 정확하지 않습니다.

문자 자료형 char

char는 1바이트 정수형입니다. 문자를 저장할 때는 그 문자의 코드값을 저장합니다. 2장에서 본 것처럼 'A'는 65이므로 char c = 'A';와 char c = 65;는 완전히 같습니다.

sizeof 연산자

sizeof는 자료형이나 변수가 차지하는 바이트 수를 컴파일 시간에 계산해 주는 연산자입니다(함수가 아닙니다). 결과의 자료형은 size_t이며 %zu로 출력합니다. 자료형에는 괄호가 필수(sizeof(int))이고 변수에는 생략할 수 있습니다(sizeof balance).

여기서 잠깐 — 고정 폭 정수형 <stdint.h>

플랫폼마다 크기가 다른 문제를 피하려고 C99는 <stdint.h>에 정확한 비트 수를 이름에 담은 자료형을 정의했습니다: int8_t, int16_t, int32_t, int64_t와 부호 없는 uint8_t~uint64_t. 출력은 <inttypes.h>의 매크로를 써서 printf("%" PRId64 "\n", x);처럼 합니다. 파일 레코드나 전문 구조체처럼 크기가 바이트 단위로 정확해야 하는 곳에서 특히 중요합니다.

초기화하지 않은 변수: 쓰레기값

왜 그럴까? — 쓰레기값은 어디서 오는가

함수 안에서 선언한 지역 변수(자동 변수)는 스택에 공간이 잡힙니다. 스택은 함수가 호출되고 끝날 때마다 계속 재사용되는 메모리라서, 변수 자리에 이전에 다른 함수가 쓰고 남긴 값이 그대로 남아 있습니다. C는 성능을 위해 이 자리를 0으로 지워 주지 않습니다. 그래서 초기화하지 않은 지역 변수의 값은 '정해지지 않은 값(indeterminate value)'이며, 이를 읽는 것은 대부분의 경우 미정의 동작입니다. 디버그 빌드에서는 0이 나오다가 최적화 빌드에서만 이상한 값이 나오는 식으로 재현이 어려운 버그가 됩니다. 반면 함수 밖의 전역 변수와 static 변수는 자동으로 0으로 초기화됩니다(13장).

이렇게 해결합니다

  • 변수는 선언과 동시에 초기화하는 습관을 들입니다: long long total = 0;
  • gcc -Wall -Wextra -O2로 컴파일해 -Wuninitialized, -Wmaybe-uninitialized 경고를 확인합니다.
  • 합계·건수 같은 누적 변수는 반복문 직전에 0으로 초기화되었는지 코드 리뷰에서 반드시 확인합니다.

은행 시스템에서는 — 일마감 합계가 매일 조금씩 다른 이유

일마감 배치에서 지점별 입금 합계를 내는 함수가 있다고 합시다. 개발자가 합계 변수를 초기화하지 않았는데, 테스트 서버에서는 우연히 그 스택 자리가 0이어서 항상 맞았습니다. 운영 서버에서는 앞서 실행된 함수가 남긴 값이 섞여 매일 합계가 원장과 맞지 않는 '대사 불일치'가 발생합니다. 이런 버그는 재현이 어렵고, 금액이 틀린 채 회계 시스템에 넘어가면 피해가 큽니다. 그래서 금융권 정적 분석 규칙에서 '초기화되지 않은 변수 사용'은 가장 높은 등급의 결함으로 분류됩니다.

const: 바꿀 수 없는 변수

변수 선언 앞에 const를 붙이면 초기화 이후 값을 바꿀 수 없는 읽기 전용 변수가 됩니다. 수수료, 한도, 세율처럼 프로그램 안에서 바뀌면 안 되는 값에 씁니다.

왜 그럴까? — 그냥 숫자 500을 쓰면 안 될까?

코드 곳곳에 500이 흩어져 있으면 (1) 그 500이 수수료인지, 건수 제한인지, 다른 의미인지 알 수 없고, (2) 수수료가 바뀌면 모든 500을 찾아 고쳐야 하는데 다른 의미의 500까지 바꿔 버릴 위험이 있습니다. 이런 의미 없는 숫자를 매직 넘버(magic number)라고 부르며 코드 품질 점검에서 지적 대상입니다. const 변수나 #define 매크로(19장)로 이름을 붙이면 의미가 드러나고 한 곳만 고치면 됩니다. 또 실수로 값을 바꾸려 하면 컴파일러가 막아 줍니다. 참고로 C의 const 변수는 C++와 달리 '상수 표현식'이 아니므로 전역 배열 크기 등에는 쓸 수 없습니다.

식별자 이름 규칙

03-2데이터 입력

지금까지는 값을 코드에 직접 넣었습니다. 이제 프로그램이 실행 중에 사용자(또는 파일, 다른 프로그램)로부터 값을 받아들이도록 해 봅니다. C 표준 라이브러리의 대표 입력 함수는 scanf입니다. scanf는 편리하지만 함정이 많은 함수이므로, 동작 원리를 정확히 이해하는 것이 이 절의 목표입니다.

scanf의 기본 사용법

scanf의 첫 인수는 printf와 비슷한 서식 문자열이고, 그 뒤에는 입력값을 저장할 변수의 주소를 줍니다. &deposit의 &는 주소 연산자로, "deposit 변수가 있는 메모리 주소"를 뜻합니다.

scanf에 &가 필요한 이유

이것은 C 입문에서 가장 중요한 "왜?" 중 하나입니다. 답의 핵심은 C의 함수 호출은 값을 복사해서 전달한다(call by value)는 사실입니다.

만약 scanf("%lld", deposit);처럼 변수를 그냥 넘긴다면, scanf가 받는 것은 deposit에 들어 있던 값의 복사본(지금은 쓰레기값)입니다. scanf가 그 복사본을 아무리 바꿔도 main의 deposit은 그대로입니다. 마치 은행 창구에 통장 사본을 맡기고 "여기에 입금해 주세요"라고 하는 것과 같습니다. 사본에 도장을 찍어도 원본 통장은 변하지 않습니다.

그래서 scanf에게는 값 대신 "deposit이 사는 주소"를 알려 줍니다. 주소를 받은 scanf는 키보드에서 읽은 값을 그 주소의 메모리에 직접 써 넣을 수 있습니다. 주소 역시 복사되어 전달되지만, 주소가 같으니 같은 메모리 칸을 가리킵니다.

왜 그럴까? — &를 빼먹으면 왜 프로그램이 죽을까?

scanf("%lld", deposit)이라고 쓰면 scanf는 서식 문자열의 %lld를 보고 "다음 인수는 long long의 주소"라고 믿습니다(printf처럼 scanf도 인수의 자료형을 모릅니다). 그런데 실제로 전달된 것은 deposit의 쓰레기값입니다. scanf는 이 값을 주소로 해석해 그 번지에 8바이트를 쓰려 하고, 그 주소가 프로세스에 할당되지 않은 영역이면 운영체제가 Segmentation fault로 프로세스를 종료시킵니다. 더 나쁜 경우는 그 주소가 우연히 쓰기 가능한 다른 변수의 위치여서, 죽지 않고 다른 데이터를 조용히 망가뜨리는 것입니다. gcc -Wall은 "format '%lld' expects argument of type 'long long int *', but argument 2 has type 'long long int'" 경고로 이를 잡아 줍니다.

한 줄 요약

C 함수는 인수를 복사해서 받으므로, 함수가 호출한 쪽의 변수를 바꾸려면 그 변수의 주소를 넘겨야 합니다. scanf의 &는 그 원리의 첫 등장이며, 7장 함수와 9장 포인터에서 같은 원리가 다시 나옵니다. 단, 12장에서 배울 문자열(char 배열)은 배열 이름 자체가 주소로 변환되므로 scanf("%s", name)처럼 &를 붙이지 않습니다.

scanf는 주소를 받으므로 printf와 달리 기본 인수 승격이 일어나지 않습니다. 즉 scanf에게 "몇 바이트를 어떤 형식으로 써야 하는지"를 서식 지정자로 정확히 알려 줘야 합니다.

원금은 long long과 %lld, 연이율은 double과 %lf, 개월은 int와 %d로 각 자료형에 맞는 지정자를 씁니다. double 결과를 (long long)으로 변환하면 소수점 이하가 버려집니다(4장 형 변환). 단, 2장에서 본 것처럼 double 오차로 인해 경계값에서 1원 차이가 날 수 있다는 점이 이 방법의 한계입니다.

입력 버퍼: scanf가 실제로 하는 일

키보드로 친 글자는 곧바로 scanf에 가지 않습니다. 사용자가 Enter를 누를 때까지 운영체제(터미널)가 한 줄을 모아 두었다가, Enter를 누르면 줄바꿈 문자 '\n'까지 포함한 한 줄 전체를 프로그램의 입력 버퍼(stdin 버퍼)로 넘깁니다. scanf는 이 버퍼에서 서식에 맞는 만큼만 꺼내 가고, 나머지는 버퍼에 그대로 남겨 둡니다. 이 "남겨 둔다"는 성질이 scanf 관련 버그의 대부분을 만듭니다.

scanf의 변환 지정자별 동작 규칙을 정리하면 다음과 같습니다.

  • %d, %lld, %lf, %s 등은 읽기 전에 앞쪽의 공백 문자(스페이스, 탭, 줄바꿈)를 모두 건너뜁니다. 그래서 숫자 여러 개를 스페이스나 Enter로 구분해 입력할 수 있습니다.
  • 숫자 변환은 숫자로 해석할 수 없는 글자를 만나면 그 앞에서 멈추고, 그 글자는 버퍼에 남겨 둡니다.
  • %c는 공백을 건너뛰지 않습니다. 버퍼에 남아 있는 '\n'이나 스페이스도 문자 하나로 읽어 버립니다.
  • 서식 문자열 안의 공백 문자 하나(" ")는 "공백 문자를 0개 이상 모두 건너뛰라"는 뜻입니다.
  • 서식 문자열 안의 일반 글자(예: "%d-%d"의 -)는 입력에 그 글자가 정확히 있어야 하며, 없으면 거기서 중단됩니다.

%c와 남아 있는 줄바꿈 문제

왜 그럴까?

사용자가 50000을 치고 Enter를 누르면 버퍼에는 "50000\n"이 들어옵니다. %lld는 50000까지만 가져가고 '\n'을 남깁니다. 다음 scanf("%c", &yn)는 공백을 건너뛰지 않으므로 버퍼에 이미 있는 '\n'(코드 10)을 즉시 읽고 끝납니다. 사용자는 y/n을 입력할 기회조차 얻지 못합니다. 만약 이 코드가 if (yn == 'y')로 이체를 실행한다면 이체가 취소되는 것으로 끝나 다행이지만, 반대로 if (yn != 'n')으로 작성했다면 사용자 확인 없이 이체가 실행됩니다.

이렇게 해결합니다 — %c 앞에 공백 하나

서식 문자열 맨 앞의 공백이 버퍼에 남은 줄바꿈과 스페이스를 모두 소비하므로, 사용자가 실제로 입력한 첫 글자를 읽게 됩니다.

자주 하는 실수 — fflush(stdin)로 버퍼를 비운다?

인터넷에 흔한 fflush(stdin);은 C 표준에서 미정의 동작입니다. fflush는 출력 스트림의 버퍼를 내보내는 함수이고 입력 스트림에 대한 동작은 정의되어 있지 않습니다. 과거 일부 MSVC 버전에서 입력 버퍼를 비우는 확장 동작을 했기 때문에 퍼졌지만, VS2015 이후 MSVC와 리눅스 glibc에서는 기대대로 동작하지 않습니다. 이식성 있는 방법은 줄 끝까지 직접 읽어 버리는 것입니다.

반복문(6장)과 getchar(11장)를 미리 쓴 코드이니 지금은 "이런 관용구가 있다"고 기억해 두면 충분합니다.

scanf의 반환값 검사

scanf는 성공적으로 읽어서 저장한 항목의 개수를 반환합니다. 첫 항목부터 실패하면 0, 아무것도 읽기 전에 입력의 끝(EOF, 리눅스 Ctrl+D, 윈도우 Ctrl+Z 후 Enter)에 도달하면 EOF(보통 -1)를 반환합니다.

왜 그럴까? — 반환값을 검사하지 않으면 무슨 일이?

실행 결과 2에서 반환값을 검사하지 않았다면, amount는 초기화되지 않은 상태 그대로 다음 계산에 쓰입니다. 즉 사용자가 "만원"이라고 입력했는데 프로그램은 쓰레기값만큼 이체를 시도하는 것입니다. scanf의 반환값 검사는 선택이 아니라 필수입니다. CERT C 시큐어 코딩 규칙(ERR33-C)도 "표준 라이브러리 함수의 오류 반환을 검사하라"고 명시합니다.

잘못된 입력 처리와 무한 반복

잘못된 입력을 받으면 다시 입력받게 하고 싶은 것이 자연스럽습니다. 그런데 다음 코드는 문자를 한 번 입력하면 무한 반복에 빠집니다(반복문은 6장에서 배우지만 이 함정은 지금 알아 두어야 합니다).

이렇게 해결합니다 — 실패 시 남은 줄 비우기

마지막 실행에서 "3번"을 입력하면 scanf는 3까지 읽어 성공하고 "번\n"은 버퍼에 남습니다. 이후 다른 입력이 이어진다면 그 찌꺼기가 또 문제를 일으킬 수 있습니다. 이 때문에 실무에서는 scanf로 직접 숫자를 읽기보다, 한 줄을 통째로 문자열로 읽은 뒤(fgets) 검증하며 변환(strtol, strtoll)하는 방식을 권장합니다. 그 방법은 11장, 12장, 22장에서 완성합니다.

자주 하는 실수 — 범위를 넘는 숫자 입력

int 변수에 scanf("%d")로 99999999999처럼 범위를 넘는 수를 입력하면 어떻게 될까요? C 표준은 "변환 결과를 해당 형으로 표현할 수 없으면 동작은 정의되지 않는다"고 규정합니다. 즉 scanf는 오버플로를 알려 주지 않으며 반환값도 1(성공)일 수 있습니다. 금액 입력처럼 범위가 중요한 곳에서 scanf를 믿으면 안 되는 또 하나의 이유입니다. strtoll은 범위를 넘으면 errno를 ERANGE로 설정해 알려 주므로 검증이 가능합니다.

여러 값과 구분자가 있는 입력

%4d처럼 scanf에 폭을 주면 최대 그 글자 수까지만 읽습니다(printf의 폭은 최소였던 것과 반대). 이를 이용해 20261028처럼 구분자 없이 붙은 날짜도 scanf("%4d%2d%2d", &y, &m, &d)로 나눠 읽을 수 있습니다. 금융권 파일의 날짜 필드는 대부분 YYYYMMDD 8자리 형식입니다. 단, "2026-10-28"에서 "10"을 %2d로 읽을 때 앞의 0이 있는 "08"도 %d는 10진수로 읽으므로 8이 됩니다(%i는 0으로 시작하면 8진수로 해석하므로 "08"에서 실패합니다. 날짜에는 %d를 씁니다).

문자열 입력 맛보기와 버퍼 오버플로

왜 그럴까? — 폭 10이 왜 생명줄인가

%s는 공백이 나올 때까지 글자를 읽어 배열에 차례로 쓰고 끝에 '\0'을 붙입니다. 배열의 크기를 전혀 모릅니다. scanf("%s", name)에 11글자 이상을 입력하면 11바이트 배열 뒤의 메모리(다른 변수, 함수 반환 주소)를 덮어씁니다. 이것이 버퍼 오버플로(buffer overflow)이며, 공격자가 반환 주소를 조작해 임의 코드를 실행시키는 고전적인 해킹 기법의 출발점입니다. %10s로 폭을 주면 최대 10글자만 읽고 '\0'을 붙이므로 11바이트 안에 안전하게 들어갑니다. 남은 글자 "G"는 버퍼에 남는다는 점도 기억하십시오. 같은 이유로 C11에서 삭제된 gets는 절대 쓰면 안 됩니다.

은행 시스템에서는 — 입력 검증은 보안 점검 1순위

금융권은 전자금융감독규정과 금융보안원 가이드에 따라 정기적으로 소스 코드 보안 약점을 점검합니다. 대표 항목이 "입력값 검증 부재", "버퍼 오버플로", "부적절한 오류 처리"이며, 모두 이 절에서 본 scanf 사용 습관과 직결됩니다. 창구 단말이나 ATM에서 들어온 금액 필드에 숫자가 아닌 값, 음수, 한도를 넘는 값이 들어와도 계정계 프로그램은 절대 그대로 처리해서는 안 됩니다. 실무 원칙은 (1) 입력은 문자열로 받고, (2) 길이·문자 종류·범위를 모두 검증한 뒤, (3) 검증을 통과한 값만 숫자로 변환해 사용하며, (4) 실패하면 명확한 오류 코드를 응답하는 것입니다.

예제 3-3 난이도 ★★★

다음 프로그램에 사용자가 3 5를 한 줄에 입력하고 Enter를 눌렀습니다. 출력 결과를 쓰고, 왜 사용자에게 두 번째 입력을 묻지 않았는지 설명하십시오.

정답과 해설 보기

버퍼에 "3 5\n"이 들어옵니다. 첫 scanf가 3을 읽고 " 5\n"이 남습니다. 두 번째 scanf는 공백을 건너뛰고 5를 읽으므로 사용자를 기다리지 않습니다(그래서 "b: " 뒤에 바로 "op: "가 출력됨). 남은 "\n"을 세 번째 %c가 읽어 op는 10이 됩니다. 이처럼 scanf는 "한 번 호출 = 한 번 입력"이 아니라 "버퍼에서 필요한 만큼 꺼내기"입니다.

핵심 정리

  • 변수는 이름이 붙은 메모리 공간이며 이름, 자료형, 값, 주소를 가집니다. 자료형은 크기와 비트 해석 방법을 정합니다.
  • 선언(int a;), 초기화(int a = 0;), 대입(a = 5;)을 구분합니다. =는 오른쪽을 계산해 왼쪽에 저장하는 대입 연산자입니다.
  • 기준 환경(64비트 리눅스): char 1, short 2, int 4, long 8, long long 8, float 4, double 8바이트. 윈도우 64비트는 long이 4바이트입니다.
  • signed 정수는 2의 보수로 표현되며 오버플로는 UB입니다. unsigned 정수는 2n으로 나눈 나머지로 순환(정의된 동작)합니다. char의 부호 여부는 구현 정의입니다.
  • 금액은 long long(또는 int64_t)으로, 음수 검사가 필요한 값에는 unsigned를 쓰지 않습니다. float는 224를 넘는 정수를 정확히 표현하지 못합니다.
  • sizeof는 바이트 수를 size_t로 돌려주는 연산자이며 %zu로 출력합니다.
  • 초기화하지 않은 지역 변수는 정해지지 않은 값(쓰레기값)을 가집니다. 선언과 동시에 초기화합니다.
  • const로 바뀌면 안 되는 값을 보호하고 매직 넘버를 없앱니다. 식별자는 영문자·숫자·밑줄, 숫자로 시작 불가, 키워드 불가, 대소문자 구별.
  • scanf는 값이 아닌 주소를 받아야 변수에 쓸 수 있습니다(call by value). 문자열 배열에는 &를 붙이지 않습니다.
  • scanf 지정자는 정확히 일치해야 합니다: double은 %lf, long long은 %lld, short는 %hd.
  • scanf는 입력 버퍼에서 필요한 만큼만 꺼내고 나머지(특히 '\n')를 남깁니다. %c 앞에는 공백을 둡니다: " %c".
  • scanf의 반환값(성공 항목 수, EOF)을 반드시 검사하고, 실패 시 남은 줄을 읽어 버립니다. fflush(stdin)은 UB입니다.
  • %s에는 반드시 폭을 지정합니다(%10s). 실무에서는 fgets + strtol/strtoll로 검증하며 입력받습니다.

CS 면접 단골 질문

이 장에서 나오는 면접 질문

Q1. scanf에서 변수 앞에 &를 붙이는 이유는 무엇인가요?

C의 함수 인수 전달은 값에 의한 호출(call by value)이라 변수의 값만 복사되어 전달됩니다. scanf가 읽은 값을 호출한 쪽 변수에 저장하려면 그 변수의 메모리 주소를 알아야 하므로 주소 연산자 &로 주소를 넘깁니다. 배열 이름은 식에서 첫 원소의 주소로 변환되므로 문자열을 읽을 때는 &를 붙이지 않습니다.

꼬리 질문 대비: "C에 call by reference가 있나요?" → 엄밀히는 없고, 포인터(주소)를 값으로 넘겨 참조 효과를 냅니다. C++의 참조자(&)와 구별해야 합니다.

Q2. signed 정수 오버플로와 unsigned 정수 오버플로의 차이는?

unsigned 정수 연산은 결과를 2n으로 나눈 나머지로 취하도록 표준이 정의하므로 순환이 보장됩니다. signed 정수 오버플로는 미정의 동작이라 결과가 보장되지 않으며, 컴파일러는 오버플로가 없다고 가정하고 최적화해 오버플로 검사 코드를 제거할 수도 있습니다. 따라서 오버플로 검사는 연산 전에 범위를 비교하는 방식으로 해야 합니다.

Q3. 2의 보수란 무엇이고 왜 사용하나요?

음수를 '모든 비트를 반전한 뒤 1을 더한 값'으로 표현하는 방식입니다. 0의 표현이 하나뿐이고, 부호와 상관없이 같은 덧셈 회로로 덧셈과 뺄셈을 처리할 수 있어 하드웨어가 단순해집니다. n비트 범위는 -2n-1 ~ 2n-1-1이며, C23부터는 표준이 2의 보수 표현을 요구합니다.

Q4. 지역 변수를 초기화하지 않으면 어떤 값이 들어 있나요? 전역 변수는요?

지역(자동) 변수는 스택에 할당되며 C가 0으로 지워 주지 않기 때문에 이전에 그 자리를 쓴 데이터가 남은 정해지지 않은 값을 가지며, 이를 읽는 것은 미정의 동작이 될 수 있습니다. 전역 변수와 static 변수는 정적 저장 기간을 가지며 프로그램 시작 전에 0으로 초기화됩니다(.bss 영역). 그래서 지역 변수는 선언과 동시에 초기화하는 습관이 중요합니다.

Q5. float와 double의 차이, 그리고 금액 계산에 실수형을 쓰면 안 되는 이유는?

float는 4바이트로 유효 숫자 약 7자리, double은 8바이트로 약 15~16자리를 표현합니다. 둘 다 2진 부동소수점이라 0.1 같은 10진 소수를 정확히 표현하지 못하고, float는 224를 넘는 정수조차 정확히 못 담습니다. 금액은 오차가 누적되면 안 되므로 최소 화폐 단위의 정수로 계산하거나 10진 고정소수점 타입을 사용합니다.

Q6. const 변수와 #define 상수의 차이는?

#define은 전처리기가 텍스트를 치환하는 것으로 자료형과 범위(scope) 개념이 없고 디버거에서 이름이 보이지 않습니다. const 변수는 자료형이 있어 컴파일러의 형 검사를 받고 블록 범위를 따르며 디버깅 시 이름으로 확인할 수 있습니다. 다만 C에서 const 변수는 상수 표현식이 아니어서 case 레이블이나 (VLA가 아닌) 배열 크기에는 쓸 수 없으며, 이런 곳에는 #define이나 enum을 씁니다.

Q7. fflush(stdin)을 쓰면 안 되는 이유와 대안은?

C 표준에서 fflush는 출력 스트림(또는 마지막 연산이 출력인 갱신 스트림)에 대해서만 정의되며, 입력 스트림에 대한 호출은 미정의 동작입니다. 일부 구현에서만 버퍼를 비우는 확장 동작이 있었을 뿐 이식성이 없습니다. 대안은 getchar로 줄바꿈이나 EOF가 나올 때까지 읽어 버리거나, 처음부터 fgets로 한 줄 단위로 읽어 파싱하는 것입니다.

Q8. 버퍼 오버플로란 무엇이고 scanf에서 어떻게 막나요?

버퍼 오버플로는 할당된 메모리 크기보다 많은 데이터를 써서 인접 메모리를 덮어쓰는 결함으로, 스택의 반환 주소를 조작당하면 임의 코드 실행으로 이어집니다. scanf의 %s는 크기를 모르므로 반드시 %10s처럼 버퍼 크기 - 1의 폭을 지정해야 하고, gets처럼 길이 제한이 없는 함수는 사용하지 않습니다. 운영 코드에서는 fgets와 길이 검증을 함께 사용합니다.

꼬리 질문 대비: "스택 보호 기법은?" → 스택 카나리, ASLR, NX 비트(DEP) 등이 있지만 근본 대책은 경계 검사입니다.

Q9. 엔디안(endianness)이란 무엇인가요?

여러 바이트로 된 값을 메모리에 저장하는 바이트 순서입니다. 리틀 엔디안은 낮은 주소에 낮은 자리 바이트를(x86, 대부분의 ARM), 빅 엔디안은 높은 자리 바이트를 먼저 저장합니다(IBM Power 기반 AIX 등, 네트워크 바이트 순서). 서로 다른 엔디안 시스템 간에 이진 데이터를 주고받을 때 변환하지 않으면 값이 완전히 달라지므로, 금융 전문은 숫자를 문자(ASCII)로 보내거나 htonl 같은 변환 함수를 씁니다.

연습문제 3-2 난이도 ★☆☆

int a = 10, b = 3;
a = a + b;
b = a - b;
a = a - b;
printf("%d %d\n", a, b);
정답과 해설 보기

a = 13, b = 13 - 3 = 10, a = 13 - 10 = 3. 임시 변수 없이 두 값을 맞바꾸는 기법이지만, 큰 값에서는 덧셈이 오버플로(UB)할 수 있어 실무에서는 임시 변수를 쓰는 것이 안전합니다.

연습문제 3-3 난이도 ★★☆

다음 출력 결과를 쓰고, 각 결과가 '정의된 동작', '구현 정의 동작', '미정의 동작' 중 어디에 해당하는지 쓰십시오(64비트 리눅스 gcc 기준).

unsigned char uc = 250;
uc = uc + 10;
unsigned int ui = 1;
ui = ui - 2;
printf("%d %u %zu\n", uc, ui, sizeof(long));
정답과 해설 보기

250 + 10 = 260은 int로 계산된 뒤 unsigned char로 변환되며 260 mod 256 = 4입니다(unsigned로의 변환은 정의된 동작). 1 - 2는 unsigned 순환으로 232 - 1 = 4294967295(정의된 동작). sizeof(long)이 8인 것은 구현 정의입니다(윈도우에서는 4).

연습문제 3-4 난이도 ★★☆

정답과 해설 보기
  1. scanf("%d", balance): & 누락(쓰레기값을 주소로 사용 → 충돌), 그리고 long long에는 %lld.
  2. scanf("%f", &rate): double에는 %lf.
  3. scanf("%s", &name): &name은 주소 값은 같지만 자료형이 char (*)[8]이라 형식 불일치입니다. 배열 이름 name을 쓰고, 폭 %7s로 오버플로를 막습니다.
  4. 반환값을 검사하지 않습니다.

연습문제 3-5 난이도 ★★☆

사용자가 42abc(앞에 공백 2개)를 입력하고 Enter를 눌렀습니다. int n = 0; int r = scanf("%d", &n); 실행 후 r과 n의 값, 그리고 입력 버퍼에 남은 내용을 쓰십시오.

정답과 해설 보기

연습문제 3-7 난이도 ★★★

정답과 해설 보기

첫 scanf 뒤 버퍼에 남은 '\n'을 %c가 읽어 confirm이 줄바꿈 문자가 됩니다. 그래서 [ 다음에 줄이 바뀌고 ]가 출력되며, 사용자는 Y를 입력할 기회도 없이 프로그램이 끝납니다. scanf(" %c", &confirm);으로 고치면 입력을 기다렸다가 [Y]가 출력됩니다.

연습문제 3-8 난이도 ★★☆

YYYYMMDD 형식의 8자리 거래일(예: 20261028)을 입력받아 년, 월, 일을 각각 int 변수에 나눠 저장하고 2026/10/28 형식으로 출력하는 프로그램을 작성하십시오.

정답과 해설 보기

scanf의 폭은 '최대 읽을 글자 수'이므로 %4d%2d%2d로 자를 수 있습니다. 출력할 때는 %02d로 앞자리 0을 유지합니다.

"01"을 %2d로 읽으면 1이 되고, 출력 시 %02d로 다시 "01"이 됩니다. 월이 13이거나 일이 32인 값의 검증은 조건문을 배운 뒤 추가해야 합니다.

연습문제 3-9 난이도 ★★★

다음 코드는 어떤 지점의 일일 입금 총액을 계산합니다. 테스트 서버에서는 항상 맞았지만 운영 서버에서는 가끔 틀립니다. 원인을 찾고 고치십시오.

정답과 해설 보기

문제가 두 가지입니다. (1) total을 초기화하지 않아 쓰레기값에서 시작합니다. 테스트 환경에서는 우연히 그 자리가 0이었을 뿐입니다. (2) 15억 + 8억 = 23억은 int 최대값(약 21.47억)을 넘으므로 signed 오버플로, 즉 UB입니다. 금액 합계는 long long으로 선언하고 0으로 초기화해야 합니다.

연습문제 3-10 난이도 ★★☆

다음 출력 결과를 쓰십시오.

char c1 = 'a', c2 = '9';
printf("%c %d %d %c\n", c1 - 32, c2 - '0', c1, c2 + 1);
정답과 해설 보기

'a'(97) - 32 = 65 = 'A'. ASCII에서 소문자와 대문자는 32 차이입니다. '9'(57) - '0'(48) = 9. c1은 97. '9' + 1 = 58이며 ASCII 58은 콜론 ':'입니다. '9' 다음 문자가 '10'이 아니라는 점에 주의하십시오.

연습문제 3-11 난이도 ★★★

float로 예금 잔액을 관리하던 프로그램에서, 잔액 20,000,001원을 저장했더니 20,000,000원으로 저장되었고, 여기에 1원을 입금해도 잔액이 계속 20,000,000원으로 출력되는 민원이 들어왔습니다. 왜 이런 일이 생기는지 float의 구조로 설명하고 대책을 쓰십시오.

정답과 해설 보기

float의 가수는 (숨은 비트 포함) 24비트이므로 224 = 16,777,216까지의 정수만 모두 정확히 표현합니다. 그 위 224 ~ 225(약 1,677만 ~ 3,355만) 구간에서는 표현 가능한 값의 간격이 2입니다. 20,000,001은 홀수라 표현할 수 없어 정확히 중간인 두 후보 중 짝수 쪽 가수를 가진 20,000,000으로 저장되고, 여기에 1을 더한 20,000,001도 다시 20,000,000으로 반올림됩니다. 즉 1원 입금이 계속 사라집니다.

대책: 금액은 long long(원 단위 정수)으로 저장·계산합니다. 기존 데이터는 정수형으로 이관하고, 과거 거래 내역으로 잔액을 재계산해 대사(對査)해야 합니다.
