37-1평가지표·과적합·하이퍼파라미터 튜닝

회귀 평가 지표

지표수식특징
MSE (Mean Squared Error)⅟ₙ Σ(y - ŷ)²큰 오차에 벌점 큼. 미분 쉬움(학습 손실함수).
RMSE√MSE원래 단위와 같아 해석 쉬움.
MAE (Mean Absolute Error)⅟ₙ Σ|y - ŷ|이상치에 둔감. 중앙값 예측에 가까움.
R²1 - SSres/SStot"분산 설명력". 1에 가까울수록 좋음. 음수 가능.
MAPE⅟ₙ Σ|(y-ŷ)/y| × 100%퍼센트 오차. y=0 근처면 폭발.

금융 수익률 예측에서 R²가 음수인 게 정상이다

R² = 1 - SSres/SStot는 "모델이 평균을 쓴 것보다 얼마나 좋은가"입니다. 수익률 예측에서 모델이 평균 수익률만 돌려주는 "0 예측기"보다 못하면 R²가 음수가 됩니다. 실제로 금융 수익률의 예측 가능한 R²는 보통 0.01~0.05에 불과하고, 그 작은 신호를 꾸준히 뽑아 포트폴리오화하는 것이 퀀트의 본질입니다. 리서치팀이 R² 0.03을 들고 와도 "낮네요" 하지 말고 "거래비용 넘길 수 있나요?"로 물어봐야 합니다.

분류 평가 지표와 혼동행렬

지표수식해석언제 중요
Accuracy(TP+TN) / 전체전체 정확도클래스 균형일 때만
Precision (정밀도)TP / (TP+FP)양성 예측 중 실제 양성 비율FP가 비쌀 때 (스팸 분류)
Recall (재현율)TP / (TP+FN)실제 양성 중 잡은 비율FN이 치명적일 때 (사기·암 진단)
F12·P·R / (P+R)P와 R의 조화평균P/R 균형이 필요할 때
ROC-AUCFPR-TPR 곡선 아래 넓이임계값과 무관한 분리력클래스 비교적 균형
PR-AUCP-R 곡선 아래 넓이불균형에 강함양성 희귀 (사기 1%)

AUC만 보면 안 되는 이유 — 불균형에서는 PR-AUC

ROC-AUC는 "양성·음성 각각에서 랜덤 뽑기 하면 양성이 더 높은 점수 받을 확률"입니다. 양성이 1%뿐인 불균형에서는 FPR 분모(음성 전체)가 너무 커서 FP가 많아도 FPR이 거의 안 올라가 ROC-AUC가 비현실적으로 좋게 보입니다. 이상거래 탐지·사기 분류에서는 반드시 PR-AUC(또는 Average Precision)를 함께 보세요.

임계값(threshold) 조정 — 비즈니스가 선택

이진 분류기의 기본 임계값은 0.5지만, 비즈니스 비용에 따라 바꿔야 합니다.

  • 신용카드 사기 탐지: FN(놓침) 비용이 매우 크므로 임계값 낮춤 → Recall↑, FP↑
  • 마케팅 타깃: 쿠폰 발송 비용 vs 전환 수익 비교 → ROC 곡선에서 Youden's J 최대점 찾기
  • 신용 승인: FP(부도난 사람 승인) 비용 vs FN(멀쩡한 사람 거절 손실) 비교

편향-분산 트레이드오프와 과적합 진단

모델 오차는 세 가지로 분해됩니다.

총 오차 = 편향² + 분산 + 노이즈(irreducible)

  • 편향(bias)이 크다 = 모델이 너무 단순해 데이터를 못 설명 (과소적합)
  • 분산(variance)이 크다 = 모델이 학습 데이터에 과하게 맞춰짐 (과적합)

과적합이 의심되면

  • 데이터를 더 모은다 (가장 근본)
  • 피처 수 줄이기 (Lasso, 피처 선택)
  • 모델 복잡도 낮추기 (max_depth↓, num_leaves↓)
  • 정규화 강화 (λ↑, dropout↑, weight_decay↑)
  • 조기 종료 (early stopping)
  • 앙상블 (랜덤포레스트, 배깅)
  • 데이터 증강 (이미지/텍스트에서)

하이퍼파라미터 튜닝

모델에는 학습으로 결정되는 파라미터(가중치)와 사람이 정하는 하이퍼파라미터(트리 깊이, 학습률 등)가 있습니다. 좋은 하이퍼파라미터 찾기는 보통 세 가지 방법.

방법원리장단
Grid Search모든 조합 전부 시도작은 공간에만 가능, 지수적 폭발
Random Search랜덤 샘플링Grid보다 거의 항상 효율적 (Bergstra 2012)
Bayesian Optimization지금까지 결과로 다음 시도 지점 예측적은 평가로 최적점, Optuna·Hyperopt

37-2해석 가능 ML(SHAP)과 시각화

왜 "해석 가능성"이 필요한가

금융에서는 성능만 좋다고 모델을 쓸 수 없습니다. 바젤 규제, 금감원 심사, 고객 설명 의무, 리스크 위원회 검토 — 전부 "왜 이 결정을 내렸는가"를 설명할 수 있어야 합니다.

  • 신용 거절 사유 통지: "AI가 거절했음"으로는 끝낼 수 없음. 어떤 변수가 영향 미쳤는지 명시 필요.
  • 리스크 모델 검증(MRM): 모델 결과를 리스크팀·내부감사가 재현·검토할 수 있어야.
  • 퀀트 알파 해석: PM이 "이 모델이 왜 이 종목을 사라는지" 설명 안 되면 집행 거절.

SHAP (SHapley Additive exPlanations)

SHAP은 게임이론의 Shapley value를 ML에 적용한 기법입니다. 각 피처가 "최종 예측에 얼마나 기여했는지"를 공정하게 분배합니다.

직관: "피처 A가 있을 때와 없을 때 예측이 얼마나 달라지는가"를 모든 피처 조합에 대해 평균 낸 것.

"알파 소스" 분해에 SHAP

XGBoost 기반 종목 선택 모델에 SHAP을 적용하면 "이 종목을 매수 추천한 이유 = 밸류 팩터 +15%, 모멘텀 -3%, 퀄리티 +8%"처럼 분해할 수 있습니다. 포트폴리오 전체 수준에서 피처별 SHAP 합을 누적하면 "이번 달 알파의 60%는 밸류, 25%는 모멘텀, 15%는 퀄리티에서 나왔다"는 알파 소스 리포트가 됩니다. 이는 PM과 리스크팀 모두가 요구하는 설명력입니다.

Permutation Importance와 Partial Dependence

Permutation Importance: 테스트셋에서 한 피처의 값을 랜덤하게 섞은 뒤 성능 하락을 측정. 하락이 클수록 중요. 모델 종류와 무관하게 쓸 수 있고 다중공선성에 대한 왜곡이 트리 내장 중요도보다 적습니다.

Partial Dependence Plot (PDP): 한 피처 값을 바꿔 가면서 평균 예측이 어떻게 변하는지 그래프. 피처와 타깃의 관계가 선형인지, 임계값이 있는지, 비선형인지 보여 줍니다.

시각화 — 결과를 "말이 되게" 보여 주기

분석 결과를 비즈니스에 전달할 때 어떤 그래프를 쓰느냐로 설득력이 달라집니다.

목적그래프
분포 비교히스토그램, 밀도 그래프(KDE), 바이올린 플롯
두 변수 관계산점도, 산점도 + 회귀선(regplot)
이상치·사분위박스플롯
변수 간 상관상관행렬 히트맵
시간 추이선그래프, 영역그래프, 누적수익률 플롯
피처 중요도수평 막대그래프, SHAP summary

백테스트 지표 — 퀀트 전용

퀀트 모델의 "모형 평가"는 수익률 지표만으론 부족합니다. 리스크 조정 수익률과 꼬리 리스크를 함께 봐야 합니다.

지표수식의미
샤프 비율(Sharpe)(평균수익 - 무위험) / 표준편차리스크 1단위당 초과수익. 연율화하면 보통 ×√252.
소르티노 비율(평균수익 - 목표) / 하방 편차샤프의 변동성 대신 하방만 — 상승 변동은 벌점 안 줌
MDD (Max Drawdown)min((누적수익 - 피크) / 피크)최대 손실폭. 체감 리스크의 핵심.
Calmar연수익 / |MDD|샤프의 MDD 버전
Information Ratio(초과수익 평균) / Tracking Error벤치마크 대비 알파의 안정성
Hit Ratio수익 거래 수 / 전체 거래 수높을수록 심리적 안정, 반드시 좋은 전략은 아님

샤프 2.0 백테스트를 무조건 믿지 마라

백테스트 샤프 비율이 2.0 이상이면 거의 확실히 다음 중 하나입니다. (1) 데이터 누수(34장), (2) 거래비용·시장충격·슬리피지 미반영, (3) 과적합(테스트 기간을 보면서 튜닝), (4) 전략의 과도한 레버리지로 분산 왜곡. 실거래 샤프는 백테스트의 50~70%로 떨어지는 것이 보통입니다. 백테스트 결과를 평가할 때는 "최악의 1년", "최악의 1개월", "MDD 복구 기간", "거래비용 가정"을 함께 봐야 합니다.

예제 37-1 — 지표 선택 난이도 ★★☆

은행이 신용카드 이상거래 탐지 모델을 평가 중입니다. 전체 거래 1000만 건 중 사기 거래는 1000건(0.01%). 모델 A는 Accuracy 99.95%, Precision 70%, Recall 15%. 모델 B는 Accuracy 99.80%, Precision 25%, Recall 85%. 어느 모델을 선택해야 할까요?

정답과 해설 보기

Accuracy는 전부 "정상"으로 찍어도 99.99%가 나오는 극단적 불균형이라 무의미합니다. 사기 탐지의 핵심은 "실제 사기를 얼마나 잡느냐 = Recall"이지만, Precision이 너무 낮으면 정상 거래의 FP 폭증으로 운영 비용(수동 확인 콜센터)이 터집니다. 비즈니스 비용 분석이 필요합니다: 모델 B는 사기 850건을 잡지만 정상 2550건을 오탐(85%/25%*1000 = 3400 양성 예측 중 2550이 오탐). 모델 A는 사기 150건만 잡고 FP 64건으로 깔끔. 사기 손실 평균이 100만원, 수동 확인 비용이 1만원이면 B가 유리(850×100만 - 2550×1만 = 8.24억 vs A의 150×100만 - 64×1만 = 1.49억). 사기 손실이 작고 콜센터 부담이 크면 A가 유리할 수 있습니다. 따라서 지표만 보지 말고 비즈니스 비용 함수(cost matrix)를 먼저 정의하는 것이 올바른 순서입니다. 추가로 PR-AUC를 비교하면 임계값 선택과 무관한 분리력을 볼 수 있습니다.

핵심 정리

  • 회귀는 MSE/RMSE/MAE/R². 금융 수익률 예측에서 R²가 음수인 건 흔한 일.
  • 분류는 혼동행렬이 뿌리. 불균형 데이터에서는 Accuracy 금지, PR-AUC·F1 사용.
  • 임계값은 비즈니스 비용에 맞춰 조정. 기본 0.5는 참고일 뿐.
  • 편향-분산 트레이드오프: 과적합이면 분산 감소, 과소적합이면 편향 감소.
  • 튜닝은 Random Search 또는 Bayesian(Optuna)이 Grid보다 거의 항상 효율.
  • 해석은 SHAP + Permutation Importance + PDP의 3종 세트.
  • 퀀트 백테스트는 수익률만 보면 함정. 샤프·MDD·거래비용·누수까지 함께.

면접 질문

자주 나오는 질문

Q1. ROC-AUC와 PR-AUC의 차이, 언제 어느 걸 쓰나요?

ROC-AUC는 FPR-TPR 곡선 넓이로 "양·음성에서 랜덤 뽑기 시 양성이 더 높은 점수 받을 확률"입니다. 클래스가 어느 정도 균형일 때 안정적. PR-AUC는 Precision-Recall 곡선 넓이로 양성 희귀한 상황에서 더 민감합니다. 사기(1%), 암 진단(0.1%) 같은 극단 불균형에서는 ROC-AUC가 비현실적으로 좋아 보이므로 반드시 PR-AUC를 함께 봅니다.

Q2. 과적합을 어떻게 진단하고 어떻게 해결하나요?

진단: (1) 학습 성능 >> 검증 성능, (2) 학습 샘플 늘려도 검증 성능 안 오름, (3) 모델 복잡도 올리면 검증 하락. 해결 순서: 더 많은 데이터 → 피처 수 줄이기(Lasso) → 모델 단순화(max_depth↓) → 정규화 강화(λ↑, dropout↑) → early stopping → 앙상블(bagging). 금융은 데이터 수집이 어려우니 정규화와 조기종료가 특히 중요합니다.

Q3. 하이퍼파라미터 튜닝에서 Grid Search 대신 Random Search를 쓰는 이유?

Grid는 중요한 파라미터와 안 중요한 파라미터에 같은 "조밀도"를 할당해 낭비가 큽니다. Random은 같은 예산으로 중요한 파라미터 축에서 더 다양한 값을 샘플링해 결과가 거의 항상 더 좋습니다. Bergstra&Bengio(2012)가 이걸 수학적·경험적으로 보였습니다. 더 나아가 Bayesian Optimization(Optuna)은 이전 결과를 활용해 유망한 영역을 집중 탐색, 같은 예산으로 더 좋은 해를 찾습니다.

Q4. SHAP과 트리 내장 feature_importances_의 차이?

트리 내장 중요도는 "학습 중 분기 기여도 합"으로 (1) 다중공선성에 임의 배분, (2) 카디널리티 높은 변수 과대평가, (3) 학습셋 기준. SHAP은 게임이론 Shapley value를 쓰므로 공정 분배가 수학적으로 보장되고, 테스트셋이나 임의 데이터에 적용 가능하며, 샘플 하나하나에 대한 설명(local explanation)도 가능합니다. 단, 계산 비용이 크고 TreeSHAP(트리 전용 고속 알고리즘)이 아니면 모델 크기에 따라 수십 분 이상 걸릴 수 있습니다.

Q5. 백테스트 샤프 비율 2.5가 나왔습니다. 믿어도 될까요?

거의 항상 과대 추정입니다. 체크리스트: (1) point-in-time 데이터인가? (34장), (2) 생존 편향 없나?, (3) 거래비용·슬리피지·시장충격 반영했나?, (4) 리밸런싱 빈도가 유동성 범위 안인가?, (5) 테스트 기간을 보고 튜닝한 적 없나?, (6) 전략 레버리지는?, (7) 하방 꼬리 손실(MDD)은 감내 가능한가? 이 모든 걸 통과한 샤프 2.5면 유니콘입니다. 보통은 1.0 미만으로 떨어지는 것이 현실입니다.
