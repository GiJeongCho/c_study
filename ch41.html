멀티모달 모델과 빌리언별 성능 비교

텍스트·이미지·음성·비디오를 한 모델이 함께 다루는 "멀티모달" 시대가 2023~2025년 사이에 완전히 열렸습니다. CLIP의 공유 공간에서 시작해 Flamingo·GPT-4V·Gemini·GPT-4o·Claude 4·Llama 3 Vision까지 왔습니다. 그런데 "어떤 모델을 써야 하지?"는 여전히 어려운 질문입니다. 이 장은 멀티모달 아키텍처의 패턴을 정리하고, 공개된 벤치마크(MMLU·HumanEval·GSM8K·MMMU·LMSYS Arena ELO) 기반 빌리언별 성능 비교표로 모델 선택을 돕습니다.

이 장에서 배울 것

  • 멀티모달이란: 왜 CLIP이 시작점이고 왜 "네이티브 omni"가 다른가
  • 멀티모달 아키텍처 패턴 4가지 — Late fusion · Early fusion · Cross-attention · MoE
  • 주요 모델 변천: CLIP → Flamingo → GPT-4V → Gemini → GPT-4o → Claude Opus 4
  • 빌리언별 성능 비교표 — MMLU · HumanEval · GSM8K · MMMU · Arena ELO · 가격
  • 소형(≤10B) · 중형(10~70B) · 대형(≥100B) · 프런티어 각 구간의 최적 선택
  • MoE(Mixture of Experts)는 왜 "총 파라미터"와 "활성 파라미터"가 다른가
  • 금융/OMS 멀티모달 활용과 모델 선택 가이드라인

41-1멀티모달이란: 아키텍처 패턴과 모델 변천

멀티모달 = "여러 입력 양식을 공유 공간에"

단일 모달 모델(텍스트 LLM, 이미지 CNN)은 자기 영역만 다룹니다. 멀티모달 모델은 서로 다른 입력(텍스트·이미지·음성·비디오)을 같은 벡터 공간 또는 같은 토큰 시퀀스로 녹여 함께 처리합니다. 2021년 CLIP이 "이미지와 텍스트를 같은 임베딩 공간에 심자"로 시작해, 2024년 GPT-4o는 "텍스트·이미지·음성을 같은 토큰 흐름으로"까지 왔습니다.

41-2빌리언별 모델 성능 비교표 — MMLU·HumanEval·GSM8K·MMMU·Arena ELO

모델 크기(파라미터 수, Billion)와 성능을 함께 보면 "이 작업엔 몇B 모델이 필요한가"가 명확해집니다. 아래 표는 공개된 공식 리포트와 LMSYS Chatbot Arena 수치(2024~2025)를 모아 정리한 것입니다. 벤치마크는 모델 버전·테스트 조건에 따라 달라지니 참고용으로 보세요.

벤치마크 한 줄 설명

  • MMLU (Massive Multitask Language Understanding): 57개 분야 객관식 지식·추론 (법률·의학·수학 등). 사람 평균 ~34%, 전문가 ~90%.
  • HumanEval: Python 함수 164개를 자연어 설명으로 작성 (pass@1). 코딩 능력.
  • GSM8K: 초등~중등 수준 수학 문제 8,500개. 다단계 추론.
  • MMMU (Massive Multi-discipline Multimodal Understanding): 이미지 + 텍스트 복합 추론 (차트·도표·수식 포함).
  • LMSYS Arena ELO: Chatbot Arena에서 사람 투표 기반 체스식 Elo. "실사용 느낌" 랭킹. 1200 평범, 1300+ 상위, 1400+ 최상위 (2025 기준).
  • 가격: API 호출 시 1M 토큰당 입력·출력 USD. 로컬 오픈웨이트는 하드웨어 비용만.

표를 읽을 때 주의할 점

  • 수치는 공식 리포트·LMSYS 기준 2024~2025 공개 데이터. 모델이 업데이트되거나 평가 조건이 다르면 숫자가 달라집니다. 최종 선택은 반드시 사내 평가셋으로 재검증.
  • "-"는 해당 벤치마크 수치가 공식 공개되지 않은 경우. 다른 소스에선 수치가 있을 수 있음.
  • 프런티어 모델의 파라미터 수는 대부분 미공개. GPT-4 1.76T 같은 숫자는 추정치.
  • MoE 모델은 "총 파라미터 / 활성 파라미터"가 다름. 저장은 전체 필요, 추론은 활성만. 비용 계산 유의.
  • 가격은 매우 자주 바뀜. 최신 가격은 각 공급사 공식 페이지 확인.
  • Arena ELO는 "실사용 선호"이지 "지능"이 아님. 작업 특성에 따라 벤치마크 순위와 Arena 순위가 다름.

같은 "크기"에서 성능이 왜 다른가 — 네 가지 변수

  • 학습 토큰 수: 같은 7B여도 1조 토큰과 15조 토큰 학습 모델은 성능이 다르다. Chinchilla 법칙: 데이터와 파라미터는 1:20 비율이 효율적.
  • 데이터 품질·커리큘럼: Phi-3는 소형(3.8B)이지만 "교과서 품질" 데이터로 Mistral 7B 수준.
  • Post-training (SFT·RLHF·DPO): 같은 base model이라도 instruct 튜닝 품질에 따라 Arena ELO가 100+ 차이.
  • MoE vs Dense: 671B MoE(DeepSeek V3)는 활성 37B만 쓰여 70B dense 수준 비용으로 프런티어 성능.

하나증권 OMS 운영 관점의 멀티모달 조합 예시

현장형 모델 포트폴리오

  1. 로컬 사내 LLM (민감 데이터 전용): Llama 3.3 70B 또는 Qwen2.5 72B · GPU 서버 1~2대. 고객정보·내부전략이 들어가는 모든 LLM 작업은 여기로.
  2. 저비용 대량 작업: Gemini 2.0 Flash 또는 GPT-4o Mini. 로그 분류·단순 요약·초안 생성 등 수만 건 처리.
  3. 고품질 분석: Claude 3.5 Sonnet 또는 GPT-4o. 리서치 리포트 요약, 대시보드 이미지 해석, 복합 추론.
  4. 장시간 코딩 에이전트: Claude Opus 4 또는 Claude Code · 운영 스크립트·대시보드 수정 등 개발 작업.
  5. 음성 분석: 사내 Whisper large-v3-turbo + Llama 3.3 70B. 실적콜·콜녹취 전부 사내 처리.
  6. 비전 (eKYC, OMS 스크린샷): Llama 3.2 Vision 90B 사내 또는 Claude 3.5 Sonnet (민감도 낮은 경우).

원칙: "민감도에 따라 사내/외부", "작업 복잡도에 따라 소형/중형/프런티어", "응답속도 중요도에 따라 Flash/Mini 또는 Pro". 한 모델에 올인하지 말고 라우팅.

"어떤 LLM 쓰세요?"에 대한 좋은 답

면접관은 "Claude가 최고" 같은 답이 아니라 "작업 유형과 민감도에 따라 라우팅합니다"를 듣고 싶어 합니다. 예: "민감 데이터는 사내 Llama 3.3 70B, 대량 분류는 GPT-4o Mini나 Gemini Flash, 중요 분석은 Claude 3.5 Sonnet, 복잡 추론은 o1을 씁니다. 매월 벤치마크를 보고 라우팅 규칙을 업데이트합니다." 이게 운영자의 모델입니다.

예제 41-1 — 모델 선택 결정 난이도 ★★☆

다음 각 요구에 가장 적절한 모델을 고르고 이유를 설명하세요(2025년 기준).

  1. 매일 100만 건의 OMS 로그를 "정상/주의/긴급" 3단계로 분류
  2. 리서치 애널리스트의 "삼성전자 메모리 사이클 분석" 보고서를 PDF 100장과 함께 요청
  3. DART 공시 PDF에서 테이블·차트의 수치를 정확히 뽑기
  4. 민감한 고객 상담 음성 → 쟁점 요약 (사내 처리 필수)
  5. Cursor로 OMS 모니터링 대시보드 재작성 (수 시간 걸릴 작업)
정답과 해설 보기
  1. Gemini 2.0 Flash 또는 GPT-4o Mini. 대량·단순 분류니 저비용 모델. 민감 로그면 사내 Qwen2.5 7B.
  2. Claude 3.5/3.7 Sonnet 또는 Gemini 2.5 Pro. 장문 + 수치 정확도. 사내 민감이면 Llama 3.3 70B.
  3. Gemini 2.5 Pro (MMMU 81.7로 가장 높음) 또는 Claude 3.7 Sonnet. 차트·표의 정량 추출은 MMMU 점수를 보면 됨.
  4. 사내 Whisper large-v3-turbo + 사내 Llama 3.3 70B. 민감 데이터는 외부 API 금지. 100% 사내 처리.
  5. Claude Opus 4 또는 Claude 3.7 Sonnet via Cursor/Claude Code. 장시간 에이전트 작업은 Claude 계열이 현재 가장 안정. Opus 4는 비싸지만 복잡 작업에 효율적.

핵심: (1) 민감도 체크 먼저, (2) 작업 유형(분류·장문·추론·코딩)에 맞게, (3) 체급을 비용으로 거꾸로 조절. 벤치마크 숫자 자체보다 "작업↔벤치마크 매핑"이 중요.

핵심 정리

  • 멀티모달은 서로 다른 입력을 공유 공간/토큰으로 녹여 함께 처리하는 모델. CLIP(2021)이 시작, GPT-4o(2024)로 네이티브 omni 시대 개막.
  • 아키텍처 4패턴: Late fusion(CLIP) · Early fusion(GPT-4o) · Cross-attention(Flamingo) · MoE(DeepSeek V3). 최근은 Early + MoE 조합이 대세.
  • 주요 벤치마크: MMLU(지식), HumanEval(코딩), GSM8K(수학), MMMU(멀티모달), LMSYS Arena ELO(실사용).
  • 소형(≤10B): 로컬·엣지. Phi-3.5 Mini, Qwen2.5 7B, Llama 3.1 8B, GPT-4o Mini.
  • 중형(10~70B): 사내 서버 실용. Qwen2.5 32B/72B, Llama 3.1/3.3 70B.
  • 프런티어: Claude 3.5/3.7 Sonnet · Claude Opus 4 · GPT-4o/4.5 · Gemini 2.5 Pro · DeepSeek R1 · o1/o3.
  • MoE는 "총 파라미터"와 "활성 파라미터"가 다름 — DeepSeek V3는 671B/37B로 70B급 비용에 프런티어 성능.
  • 같은 크기에서 성능이 다른 이유: 학습 토큰 수(Chinchilla), 데이터 품질, Post-training, MoE 여부.
  • 금융/OMS 라우팅 원칙: 민감 데이터는 사내 오픈웨이트, 대량 저단가는 Flash/Mini, 중요 분석은 Sonnet·Pro, 복잡 추론은 o1/R1, 장시간 에이전트는 Claude Opus 4.
  • 벤치마크 숫자는 참고용. 최종 선택은 사내 평가셋으로 재검증. 매월 라우팅 규칙 업데이트.

면접 질문

자주 나오는 질문

Q1. 멀티모달 모델이란 무엇이고 왜 중요한가요?

텍스트·이미지·음성·비디오 등 서로 다른 입력 양식을 하나의 모델이 함께 다루는 것입니다. 중요한 이유는 (1) 실제 금융 업무가 이미 멀티모달 — 공시 PDF는 텍스트+차트+표, 실적콜은 음성+전사, 리서치 리포트는 텍스트+그림, (2) pipeline(ASR→LLM→TTS)과 비교해 지연·정확도·자연스러움에서 크게 유리, (3) RAG·에이전트가 멀티모달 입력을 다룰 수 있어 활용 범위가 폭발적으로 늘어남. 하나증권에서도 OMS 대시보드 스크린샷·공시 PDF·실적콜 녹음을 한 파이프라인으로 처리할 수 있게 됐습니다.

Q2. 모델 크기 "B"는 뭘 뜻하고 왜 중요한가요?

Billion(10억) 파라미터입니다. 가중치 개수 자체도 중요하지만, 더 중요한 건 (1) 추론 비용: 크면 GPU 메모리와 지연이 늘어남, (2) 학습·배포 비용: 사내 호스팅 시 하드웨어 결정, (3) 성능 상한: 보통 크면 똑똑하지만 "학습 토큰 수·데이터 품질"이 더 결정적이기도 함. Chinchilla 법칙에 따르면 파라미터 1B당 20B 토큰 학습이 효율적입니다.

Q3. MoE(Mixture of Experts)는 왜 중요한가요?

총 파라미터가 커도 "활성 파라미터"만 쓰여 비용이 작습니다. DeepSeek V3는 총 671B지만 활성은 37B라, 추론 비용은 70B dense 수준에 프런티어 성능을 냅니다. 각 토큰마다 Router가 "어느 전문가(expert)를 쓸지" 결정해 상위 k개(보통 2개)만 활성화. 장점은 저비용·고성능, 단점은 (a) 저장 공간은 전체 필요, (b) 학습이 불안정, (c) 로드밸런싱이 어려움. GPT-4·Gemini도 MoE로 추정되고 있고, 2025년 현재 거대 모델의 사실상 표준입니다.

Q4. MMLU 90%면 사람 수준인가요?

단답으로는 "거의 전문가 수준의 객관식 지식"입니다. 사람 평균이 ~34%, 전문가가 ~90%, 2025년 프런티어 모델은 90% 전후. 하지만 (1) MMLU는 객관식 지식 중심이지 추론·창의성·사실 확인이 약함, (2) 벤치마크 특화 학습(contamination) 가능성, (3) 실무 작업과 괴리 — 즉 "MMLU 2점 더 높다"가 "실무 더 유용"이 아님. 그래서 LMSYS Arena ELO 같은 "실사용 선호" 지표도 함께 봐야 합니다.

Q5. 하나증권 OMS에서는 어떤 모델을 어떻게 조합하시겠어요?

작업 유형과 민감도로 라우팅합니다. (1) 민감 데이터 (고객정보·내부전략): 사내 Llama 3.3 70B 또는 Qwen2.5 72B. (2) 대량 로그 분류·단순 요약: Gemini 2.0 Flash 또는 GPT-4o Mini. 저단가 대량. (3) 리서치·대시보드 분석: Claude 3.5 Sonnet 또는 Gemini 2.5 Pro. 멀티모달 정확도. (4) 장시간 코딩 에이전트: Claude Opus 4 via Cursor/Claude Code. (5) 음성: 사내 Whisper large-v3-turbo + 사내 LLM. 핵심은 "한 모델에 올인 안 하고 라우팅", "매월 벤치마크 업데이트 보면서 라우팅 규칙 조정". 그리고 사내 평가셋으로 반드시 재검증합니다.

Q6. 오픈웨이트 모델(Llama, Qwen, DeepSeek)과 프로프라이어터리(GPT, Claude, Gemini)의 선택 기준은?

(1) 민감 데이터 다루면 오픈웨이트 + 사내 호스팅이 거의 필수. (2) 최고 성능이 필요하면 2025년 현재 프런티어 프로프라이어터리(Claude 4·Gemini 2.5·GPT-4o 계열)가 여전히 선두 — 다만 DeepSeek V3/R1이 격차를 많이 좁힘. (3) 장기 비용: 사용량이 많으면 오픈웨이트 자가호스팅이 유리. (4) 규제·감사: 금융권은 데이터 흐름·모델 버전 통제가 필요해 오픈웨이트가 유리한 측면. (5) 속도·안정성: 프로프라이어터리 API가 자가호스팅보다 더 안정적일 때가 많음. 실무에선 둘을 조합합니다.
