데이터 전처리와 분석 모형 설계

머신러닝에서 모델이 전부가 아닙니다. 현업에서 성능을 가르는 건 "모델을 뭘 썼냐"보다 "데이터를 어떻게 다뤘냐"입니다. 이 장에서는 결측치·이상치·스케일링 같은 전처리와, 학습·검증·테스트 분할, 교차검증, 데이터 누수(data leakage) 같은 분석 모형 설계의 핵심을 다룹니다. 빅데이터분석기사 3과목의 가장 중요한 뿌리이자, 퀀트 백테스트에서 "미래 정보가 과거로 새어 들어가는" 치명적 사고를 막는 기본기입니다.

이 장에서 배울 것

  • 구조화·반구조화·비정형 데이터의 차이와 금융 데이터의 특성
  • 결측치, 이상치, 중복 제거의 원리와 코드
  • 표준화(Z-score), 정규화(Min-Max), 로버스트 스케일링의 차이와 금융 데이터 선택 기준
  • 범주형 인코딩(원-핫, 라벨, 타깃)의 함정
  • 학습/검증/테스트 분할, K-fold 교차검증, 시계열 교차검증
  • 데이터 누수(data leakage) 사례와 방지법 — 퀀트 백테스트의 1급 사고
  • 클래스 불균형 처리(SMOTE, 가중치, under/over sampling)

34-1데이터 이해와 전처리

머신러닝 프로젝트에서 가장 많은 시간을 쓰는 단계가 바로 데이터 전처리입니다. 흔히 "ML 엔지니어 시간의 80%는 데이터 정제"라고 합니다. 특히 금융권에서는 데이터 소스가 많고(원장 DB, 체결 로그, 시세, 뉴스, 공시, 리서치 리포트) 각 소스마다 스키마·시간대·결측 패턴이 전부 달라서, 전처리 품질이 모델 성능보다 중요한 경우가 흔합니다.

데이터의 종류와 금융 데이터의 특성

데이터는 구조에 따라 세 가지로 나뉩니다.

종류예시특징금융/퀀트 예
구조화 데이터CSV, RDB 테이블행·열이 명확, 스키마 고정시세 OHLCV, 체결 원장, 재무제표
반구조화 데이터JSON, XML, 로그태그/키-값 구조는 있지만 유연OMS 전문(電文), REST API 응답, FIX 메시지
비정형 데이터텍스트, 이미지, 음성스키마 없음, NLP·CV 필요뉴스 기사, 공시 PDF, 애널리스트 리포트

금융 데이터는 몇 가지 공통된 특성이 있습니다.

  • 시간 축이 핵심이다. 같은 종목·같은 가격이라도 시점이 다르면 다른 데이터.
  • 결측이 흔하다. 상장폐지, 거래정지, 신규상장, 종목코드 변경, 분할·합병 등으로 과거 데이터가 "원래 없는" 경우가 많다.
  • 이상치가 진짜 신호일 수 있다. 하한가/상한가, 대량 체결은 노이즈가 아니라 중요한 사건.
  • 생존 편향(survivorship bias): 현재 상장돼 있는 종목만 보면, 과거에 상장폐지된 "망한 종목"이 데이터셋에서 사라져 수익률이 과대평가된다.
  • 미래 정보 누수(look-ahead bias): 2024년 12월에 발표된 재무제표를 2024년 1분기 수익률 예측에 쓰면 치팅.

현장 사례 — "백테스트는 100%인데 실전은 -20%"

신입 퀀트가 가장 많이 겪는 사고입니다. 백테스트 결과가 비현실적으로 좋으면 90% 이상이 데이터 누수 또는 생존 편향입니다. "미래의 재무제표가 과거 날짜에 쓰였다", "거래정지 기간을 평균 수익률로 메꿨다", "상장폐지된 종목이 유니버스에서 빠졌다" 같은 것들입니다. OMS 운영자가 리서치팀의 모델 리뷰에 참여할 때 반드시 체크하는 포인트입니다.

결측치, 이상치, 중복 처리

결측치(missing value)는 "값이 비어 있는" 데이터입니다. pandas에서는 NaN으로 표현됩니다. 처리 방법은 크게 세 가지입니다.

  1. 삭제: 결측이 있는 행 또는 열을 지움. 데이터 손실이 큼. df.dropna()
  2. 대체(imputation): 평균·중앙값·최빈값 또는 다른 변수로부터 추정값을 채움. df.fillna(df.mean())
  3. 모델 자체가 결측 허용: XGBoost·LightGBM은 결측치를 그대로 받아 학습 시 분기 방향을 자동으로 결정

자주 하는 실수 — 전체 평균으로 결측 대체

테스트 데이터의 결측을 "전체(학습+테스트) 평균"으로 메꾸면 테스트 분포 정보가 학습에 새어 들어가 데이터 누수가 됩니다. 반드시 학습 데이터에서만 통계(평균·중앙값)를 계산해서 그 값을 테스트에도 적용해야 합니다. scikit-learn의 SimpleImputer를 fit_transform은 학습, transform은 테스트에 쓰는 이유가 바로 이것입니다.

이상치(outlier)는 "다른 값들에서 크게 벗어난 값"입니다. 금융에서는 상한가·하한가, 분할 전 가격, 데이터 오류(수수료 음수) 등이 섞여 있습니다.

이렇게 해결합니다 — 윈저라이징(winsorizing)

금융에서는 이상치를 지우기보다 윈저라이즈(상·하위 극단값을 백분위수 경계값으로 자르기)를 흔히 씁니다. 예: 수익률 데이터를 1%, 99% 백분위로 자르면 상·하한가 같은 극단값은 유지하되 영향을 완화할 수 있습니다. scipy.stats.mstats.winsorize 또는 pandas clip(lower=q01, upper=q99)로 구현합니다.

스케일링과 인코딩

여러 피처가 서로 다른 단위를 가지면(예: 가격은 1만원 단위, 수익률은 소수점, 거래량은 억 단위), 거리 기반 모델(KNN, SVM, K-means)이나 경사하강법 기반 모델(선형회귀, 신경망)은 큰 단위 피처에 끌려갑니다. 그래서 스케일링(scaling)이 필요합니다.

방법수식특징언제 쓰나
표준화(Standardization)(x - μ) / σ평균 0, 표준편차 1
이상치 영향 중간		정규분포 가정 모델(선형, 로지스틱, PCA, 신경망)
Min-Max 정규화(x - min) / (max - min)[0, 1] 범위
이상치에 매우 취약		신경망 입력(이미지 픽셀 등), KNN
로버스트 스케일링(x - median) / IQR이상치 영향 최소
중앙값·IQR 기반		이상치 많은 금융 데이터, 수익률
로그 변환log(1 + x)왜도(skewness) 완화가격·거래량처럼 꼬리가 긴 분포

범주형 인코딩: 모델에 넣기 전에 숫자로 바꿔야 합니다.

  • 원-핫 인코딩: 'KR', 'US', 'JP' → [1,0,0], [0,1,0], [0,0,1]. 카테고리 수가 적을 때.
  • 라벨 인코딩: 'A', 'B', 'C' → 0, 1, 2. 순서가 의미 있을 때(등급: AAA > AA > A …).
  • 타깃 인코딩: 범주별로 타깃 변수의 평균을 인코딩. 카디널리티 높은 변수(종목코드 수천 개)에 유용하나 데이터 누수 위험 큼 — 반드시 교차검증 안에서 수행.

라벨 인코딩을 트리 아닌 모델에 쓰면 안 되는 이유

선형회귀나 KNN에 'A'=0, 'B'=1, 'C'=2를 쓰면 모델이 "C는 A의 2배"로 해석합니다. 순서가 없는 범주(섹터, 통화코드)에는 원-핫을, 순서가 있는 범주(신용등급)에는 라벨을, 트리 계열(랜덤포레스트, XGBoost)에는 어떤 걸 써도 괜찮습니다.

34-2분석 모형 설계: 데이터 분할·교차검증

학습·검증·테스트의 세 집합

데이터는 반드시 세 조각으로 나눕니다.

왜 세 조각일까? 두 조각이면 안 되나?

두 조각(학습/테스트)만 두면, 하이퍼파라미터 튜닝(예: 랜덤포레스트 트리 개수)을 테스트셋 성능 보고 조정하게 되어 테스트셋이 사실상 학습셋이 됩니다. 그래서 "학습에서 모델이 배우고 → 검증에서 하이퍼파라미터 조정 → 테스트는 숨겨 뒀다가 마지막에 딱 한 번"의 세 단계가 표준입니다.

K-fold 교차검증

데이터가 적을 때 학습/검증을 한 번만 나누면 분할 운에 따라 성능이 들쭉날쭉합니다. K-fold 교차검증(cross-validation)은 데이터를 K조각으로 나누고 각 조각을 한 번씩 검증셋으로 사용해 K번 학습하고 평균을 냅니다.

시계열 교차검증 — 금융에서 반드시 알아야 할 분할

금융 데이터는 시간 순서가 있어서 일반 K-fold를 쓰면 미래 데이터로 과거를 학습하는 치명적 누수가 생깁니다. 대신 시계열 분할(TimeSeriesSplit)을 씁니다.

데이터 누수(data leakage) — 퀀트 1급 사고

데이터 누수는 "모델이 알 수 없어야 할 미래 정보가 학습에 섞여 들어간" 상태입니다. 백테스트가 비현실적으로 잘 나오면 가장 먼저 의심해야 합니다.

누수 유형예시방지
타깃 누수"다음 날 수익률"로 라벨을 만들면서 종가·시가에 미래 정보가 포함됨라벨 생성 시점의 데이터만 쓰기, shift로 명시적 시점 분리
전처리 누수전체 데이터로 평균·표준편차 계산해 스케일링Train만으로 fit, Val/Test는 transform만
그룹 누수같은 고객의 거래가 Train과 Test에 섞여 있음GroupKFold, 고객ID 단위로 분할
시간 누수2024년 데이터로 학습 후 2023년 성능 측정TimeSeriesSplit, 날짜 단위 cut-off
생존 편향현재 상장된 종목만으로 과거 백테스트시점별 유니버스 재구성, 상장폐지 종목 포함

한 줄 요약

"오늘 아침 9시에 알 수 있었던 정보만 그 시점의 모델이 쓸 수 있다." — 모든 피처에 대해 이 질문을 통과하지 못하면 누수입니다.

클래스 불균형 처리

이상거래 탐지(10만 건 중 사기 100건), 신용부도 예측(1% 미만 디폴트)처럼 양성 샘플이 매우 적으면 모델이 "전부 음성"으로 예측해도 정확도 99%가 나옵니다. 이걸 피하는 방법들입니다.

  • 클래스 가중치: 손실 함수에서 소수 클래스에 더 큰 가중치. class_weight='balanced'
  • 언더샘플링: 다수 클래스에서 랜덤 추출. 데이터 손실 큼.
  • 오버샘플링: 소수 클래스를 복제. 과적합 위험.
  • SMOTE: 소수 클래스의 두 샘플 사이를 보간해서 합성 샘플 생성.
  • 평가지표 변경: 정확도 대신 F1, PR-AUC 사용(37장).

예제 34-1 — 백테스트 누수 찾기 난이도 ★★☆

어떤 퀀트 모델이 "회사의 분기 실적 발표 후 주가 반응"을 예측합니다. 피처로 (1) 발표 당일 종가, (2) 발표일 거래량, (3) 최근 5일 평균 수익률, (4) 애널리스트 컨센서스 대비 서프라이즈를 쓰고 있습니다. 라벨은 "발표 다음 날 수익률 > 2%". 2015-2023년으로 백테스트하니 샤프비율 4.8이 나왔습니다. 누수가 있을까요?

정답과 해설 보기

피처 (1) 발표 당일 종가와 (4) 서프라이즈에 누수가 있습니다. 분기 실적은 보통 장 종료 후 발표되므로 "발표 당일 종가"는 실적 발표 전 가격이지만, 서프라이즈는 발표 시점에 알 수 있습니다. 즉, 다음날 수익률을 예측하는 시점(발표 후 야간)에는 서프라이즈를 알 수 있어 문제 없어 보이지만, 실제로는 발표가 장중에 나오는 경우(해외 공시, 코스닥 특례), 발표 당일 종가에 이미 실적 반응이 반영되어 있어 피처 자체가 라벨 정보를 담고 있습니다. 또한 컨센서스 데이터의 시점도 중요합니다: 데이터 공급사가 "리비전 반영" 컨센서스를 과거 시점에 돌려 넣는 경우가 흔한데, 이는 실시간에는 알 수 없었던 값입니다. 샤프 4.8은 거의 확실히 누수의 결과입니다. 실제 live 수익률은 음(-)이 될 가능성이 높습니다.

핵심 정리

  • 데이터 품질이 모델보다 중요하다. 전처리에 전체 작업 시간의 70~80%를 쓸 각오.
  • 결측 대체는 학습 데이터에서만 통계를 계산 — fit_transform은 Train, transform은 Test.
  • 이상치는 금융에서 종종 "진짜 사건"이다. 자동 제거 금지, 윈저라이즈 또는 보존.
  • 스케일링: 선형·신경망·KNN은 필수, 트리 계열은 불필요.
  • 데이터는 Train / Val / Test로 세 조각. 테스트셋은 최후의 1회만.
  • 금융 데이터는 반드시 TimeSeriesSplit. 일반 K-fold는 미래 정보 누수.
  • 백테스트가 비현실적으로 좋으면 90% 확률로 데이터 누수 또는 생존 편향.

자주 나오는 질문

Q1. 데이터 누수(data leakage)가 무엇이고 어떻게 방지하나요?

미래에 발생할, 또는 모델이 예측 시점에는 알 수 없는 정보가 피처에 섞여 들어가 학습에 사용되는 상태입니다. 라벨 자체가 피처에 포함되거나, 전체 데이터로 전처리 통계를 계산하거나, 시간 순서를 무시한 교차검증이 대표적 원인입니다. 방지: (1) "예측 시점에 알 수 있었나?" 질문 통과, (2) 전처리는 반드시 Train에서만 fit, (3) 금융은 TimeSeriesSplit, (4) 그룹 데이터는 GroupKFold.

Q2. StandardScaler와 MinMaxScaler, RobustScaler의 차이와 각각 언제 쓰나요?

StandardScaler는 (x-μ)/σ로 평균 0, 표준편차 1로 만듭니다. 정규분포 가정 모델에 적합. MinMaxScaler는 (x-min)/(max-min)으로 [0,1] 범위로 압축, 신경망 입력·이미지 픽셀에 흔히 씀. 이상치에 매우 취약. RobustScaler는 중앙값과 IQR을 쓰므로 이상치 영향 최소, 수익률·거래량 같은 꼬리 두꺼운 금융 데이터에 적합.

Q3. 생존 편향(survivorship bias)이란 무엇이며 어떻게 방지하나요?

현재 시점에서 "살아남은" 대상만 데이터셋에 포함되어 과거 성과가 과대평가되는 편향입니다. 예: 현재 KOSPI200 구성 종목만으로 과거 10년 백테스트를 하면, 그동안 지수에서 탈락한 부진 종목이 빠져서 수익률이 실제보다 좋게 나옵니다. 방지법은 "매 시점의 과거 유니버스를 그 시점 기준으로 재구성"하는 것입니다. 상장폐지, 지수 편입/탈락, 종목코드 변경 이력을 모두 반영한 point-in-time 데이터베이스가 필수입니다.

Q4. 클래스 불균형이 심한 데이터에서 정확도(accuracy)가 왜 나쁜 지표인가요?

이상거래 1%, 정상거래 99%인 데이터에서 "모두 정상"으로 예측하는 멍청한 모델도 정확도 99%를 얻습니다. 실제 관심 대상인 이상거래를 하나도 못 잡아도 지표가 좋게 나와 모델 비교에 쓸 수 없습니다. 이런 경우 Precision, Recall, F1, PR-AUC, ROC-AUC가 더 유용합니다.

Q5. SMOTE가 뭐고 단점은?

Synthetic Minority Over-sampling Technique. 소수 클래스의 샘플을 가까운 이웃과의 보간으로 "합성"해서 양을 늘립니다. 단순 복제보다 과적합이 적지만, (1) 노이즈 샘플 주변에도 합성해서 품질이 떨어질 수 있고, (2) 범주형 피처에는 보간이 어색하며, (3) 테스트셋에는 절대 적용하면 안 됩니다(평가가 왜곡됨).
