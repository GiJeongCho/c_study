# C언어 금융 IT 마스터

하나증권 퀀트실 OMS 운영 업무 준비를 위해 만든 **C 언어 + 금융 IT 자가학습 교안**입니다.
`printf("hello")`부터 **코어뱅킹급 미니 OMS·원장·배치**까지 한 번에 이어서 공부할 수 있도록
입문부터 실무까지를 **단일 사이트(정적 HTML)** 로 묶었습니다.

- 전부 **순수 HTML + CSS + JS** 라서 설치/빌드 없이 바로 열어 볼 수 있고,
- **PC·태블릿·스마트폰**에서 모두 읽기 좋게 반응형으로 되어 있습니다.
- 하단에 **지하철/출퇴근용 모바일 공부 팁**과 **OMS 운영 로그 분석 관점 가이드**를 같이 적어 두었습니다.

---

## 1. 열어 보는 법

### 방법 A. 그냥 더블클릭 (가장 쉬움)

`index.html` 을 더블클릭하면 됩니다. 폰트는 Google Fonts에서 받고, 나머지는 로컬 파일로만 돌아갑니다.

> ⚠️ 윈도우에서 `file://` 로 열면 일부 브라우저가 fetch/캐시 정책을 엄격하게 적용해
> 글꼴 로드가 늦어 보일 수 있습니다. 느낌이 애매하면 아래 방법 B를 쓰세요.

### 방법 B. 로컬 서버로 열기

Python 3가 깔려 있다면,

```powershell
cd C:\project\C_study
python -m http.server 8000
```

브라우저에서 `http://localhost:8000/` 접속.

### 방법 C. 모바일에서 보기

같은 Wi-Fi에 폰을 연결한 뒤 PC의 IP를 확인하고 (`ipconfig` → `IPv4`) 폰 브라우저에서

```
http://<PC의-IP>:8000/
```

로 접속하면 됩니다. (방화벽에서 8000 포트 허용 필요)
노션/옵시디언에 넣을 필요 없이 **그냥 폰 브라우저에서 북마크** 해두면 통근 시간에 바로 복습 가능합니다.

## 3. 하나증권 퀀트실 OMS 운영 관점 — 어디부터 볼까

> 하나증권 퀀트실 OMS 운영은 **직접 개발보다 로그/모니터링/운영 이슈 추적** 비중이 큽니다.
> 로그 메시지를 읽고 "왜 이 메시지가 찍혔지?"를 짚어 내려면 **C 레벨에서 메모리/전문/소켓/배치**가
> 어떻게 돌아가는지 감이 있어야 합니다. 아래 순서로 보면 가장 효율적입니다.

### A. 로그를 "읽을 수 있는 눈" 만들기 (최우선)
- **[ch30 디버깅과 장애 대응](ch30.html)** — 로그 레벨, 거래 추적 ID(GUID), 민감정보 마스킹, 로그 로테이션, **장애 대응 절차(감지→전파→원인→복구→재발방지)**, 장애 보고서 작성. OMS 운영에서 **가장 먼저 체화해야 하는 장**.
- **[ch22 시큐어 코딩](ch22.html)** — 왜 로그에 주민번호/계좌번호 전체를 찍으면 안 되는지, 왜 메모리 깨짐이 "엉뚱한 데서 터지는지".
- **[부록 D. 금융 IT 실무 체크리스트](appendix.html#sD)** — 코드 리뷰 / 배포 전 / 금액 처리 / 개인정보 / 로그 / 배치 운영 각각의 체크리스트.

### B. 전문(電文)과 소켓 — 주문/체결 메시지를 이해하기
- **[ch24 전문 처리](ch24.html)** — 고정길이 전문, 구조체 매핑, 엔디안, 패딩, 문자코드 변환.
    OMS에서 거래소/HTS/타행과 주고받는 메시지가 거의 다 이 구조입니다.
- **[ch27 네트워크 소켓 프로그래밍](ch27.html)** — TCP 소켓과 전문 송수신 서버 패턴.
    "주문이 안 나갔다", "응답이 안 왔다" 같은 장애의 1차 원인 추적에 필요.
- **[ch17 구조체 / 공용체 / 열거형](ch17.html)** — 전문을 코드로 다루는 기본기.
- **[ch20 비트 연산](ch20.html)** — 플래그·바이너리 전문 해석.

### C. 금액 정밀도와 트랜잭션 — "숫자가 안 맞아요" 사고 예방
- **[ch21 금융 계산과 정밀도](ch21.html)** — **왜 double 로 금액을 다루면 안 되는지**,
    정수 기반 금액 계산, 반올림 규칙(은행원 반올림 등).
- **[ch28 동시성](ch28.html)** — 계좌이체 경쟁 조건, 데드락.
- **[ch29 DB 트랜잭션](ch29.html)** — 커밋/롤백, TP 모니터.
- **[ch32 캡스톤: 미니 코어뱅킹](ch32.html)** — 원장·거래·전문·일마감 배치 전체를 하나로 묶는 실습.
    OMS 운영 중 "어디서 어떤 로그가 왜 찍히는지"의 큰 그림을 잡는 데 좋음.

### D. 배치와 일마감 — 야간·장후 운영의 핵심
- **[ch25 배치 프로그래밍](ch25.html)** — 대용량 파일 배치, 정합성 검증, **재처리 설계**.
- **[ch18 파일 입출력](ch18.html)** — 배치 입출력의 기본기.
- **[ch26 유닉스 시스템 프로그래밍](ch26.html)** — 시그널, IPC, 스크립트에서 자주 보는 패턴.

### E. 면접 대비는 마지막에
- **[ch33 CS 면접 총정리](ch33.html)** — 100+ 개 질문. 공부가 어느 정도 올라온 뒤 리뷰용으로.

### F. 데이터·ML·LLM — 리서치 모델 리뷰와 LLM 활용 (여유 생기면)
퀀트실 OMS 운영이라도 리서치팀 알파 모델을 **운영 관점에서 검토**할 수 있어야 하고, LLM을 **로그·장애 분석에 직접 활용**할 수 있으면 가치가 큽니다.
- **[ch34 데이터 전처리와 모형 설계](ch34.html)** — 데이터 누수·생존 편향·시계열 CV. 백테스트가 비현실적으로 좋을 때 가장 먼저 의심할 포인트들.
- **[ch35 지도학습](ch35.html)** — XGBoost/LightGBM이 왜 알파팩터 조합에 쓰이는가, 신용평가 로지스틱 회귀의 50년 전통.
- **[ch36 비지도·시계열·딥러닝](ch36.html)** — PCA로 숨겨진 시장 요인 분해, GARCH, 금융에 LSTM 쓸 때의 함정.
- **[ch37 모형 평가와 해석](ch37.html)** — 불균형(사기탐지) 지표, SHAP으로 "알파 소스" 분해, 백테스트 샤프 2.5를 믿지 않는 법.
- **[ch38 Transformer·LLM과 금융/OMS](ch38.html)** — Self-Attention과 Transformer, **LLM 학습 3단계(사전학습·SFT·RLHF)**, LLM의 "기억 못 함" 3대 원인(학습 컷오프·컨텍스트 창·세션 무상태), **지식 그래프 vs 벡터 RAG와 GraphRAG**, 프롬프트 7원칙(PROMPT 7)과 기억 재주입 패턴, **OMS 로그 요약·장애 보고서 초안·매뉴얼 Q&A 봇** 등 지금 당장 쓸 수 있는 LLM 패턴.

## 4. 공부법 가이드 (출퇴근·주말 복습용)

- **"어디서 멈췄는지"는 자동 저장됩니다.** 각 챕터 상단에 들어가는 순간
    `localStorage` 에 저장되고, 홈([index.html](index.html))에 **"이어서 보기"** 버튼이 뜹니다.
- 각 챕터 좌측 **"목차"** 버튼(모바일) 또는 좌측 사이드바(PC)로 다른 챕터로 바로 이동.
- 각 챕터 하단에 **이전/다음 챕터** 네비게이션이 자동으로 생깁니다.
- 코드 블록 우상단의 **"복사"** 버튼으로 코드를 바로 복사해서 로컬에서 돌려보세요.
- 다크/라이트 모드는 **시스템 설정**을 따라갑니다 (OS 다크 모드 켜면 자동 적용).
- **다이어그램(SVG)은 모바일에서 가로 스크롤**로 원 크기를 유지합니다. 글자가 너무 작아 보이면 다이어그램을 좌우로 스와이프하세요.
