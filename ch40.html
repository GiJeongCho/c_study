음성 AI 변천사 — ASR·TTS·실시간 음성 LLM

1952년 Bell Labs가 "0~9 숫자"를 알아듣는 Audrey를 만든 뒤 70년, 음성 AI는 HMM-GMM의 통계 모델 시대 → DNN-HMM → End-to-End 딥러닝(CTC·RNN-T·Attention) → 자기지도학습(Wav2Vec·Whisper) → 네이티브 음성 LLM(GPT-4o Realtime, Gemini Live)까지 왔습니다. 이 장은 그 변천사와 함께 콜녹취 분석·회의록·실적 발표 콜·성문인증 등 금융권에서 지금 당장 쓸 수 있는 음성 활용을 정리합니다.

  • 전통 ASR: HMM-GMM과 그 한계

  • 음성 LLM: pipeline(ASR→LLM→TTS) → 네이티브 omni 모델(GPT-4o, Gemini Live)

40-1음성 신호와 전통 ASR·CTC·RNN-T

음성 신호 — 파형에서 멜 스펙트로그램으로

음성은 공기 압력의 시간 변화입니다. 마이크가 그걸 디지털로 바꾸면 보통 16,000Hz(음성용) 또는 44,100Hz(음악용) 샘플링 레이트로 1초에 수만 개의 숫자가 됩니다. 모델이 이걸 그대로 다루기엔 너무 길어서, 보통 25ms 윈도우를 10ms씩 밀면서 스펙트로그램으로 변환합니다.

전통 ASR — HMM-GMM 시대 (1980~2010)

딥러닝 이전의 20년간 ASR의 표준은 HMM-GMM이었습니다.

  • HMM(Hidden Markov Model): 음소(phoneme)의 시간 변화를 상태 전이로 모델링. "ㅅㅏㅁㅅㅓㅇㅈㅓㄴㅈㅏ" 같은 음소 시퀀스가 숨은 상태.
  • GMM(Gaussian Mixture Model): 각 상태에서 MFCC 벡터가 나올 확률을 가우시안 혼합으로 모델링.
  • 음향모델 + 발음사전 + 언어모델의 세 축으로 작동. 셋을 WFST(Weighted Finite State Transducer)로 결합.

장점은 수학적으로 깔끔하고 적은 데이터로도 동작한다는 것, 단점은 음소 단위 라벨링이 필수고 성능 상한이 명확했다는 것입니다. 2012년 Hinton의 DNN-HMM이 GMM을 DNN으로 바꾸면서 WER이 급락했지만, 여전히 HMM의 틀은 유지했습니다.

End-to-End 혁명 — CTC와 RNN-T

2014년 Alex Graves의 CTC(Connectionist Temporal Classification)는 음성 인식의 틀을 완전히 바꿨습니다. "음성 프레임(100개)과 글자(10개)의 길이가 다르다"는 문제를 "빈 토큰(blank)을 넣어 정렬 자체도 학습"으로 풀었습니다. Baidu의 Deep Speech(2014), DeepSpeech 2(2015)가 이 접근으로 전통 시스템을 능가했습니다.

40-2Wav2Vec·Whisper·TTS와 음성 LLM

Wav2Vec 2.0 — 자기지도학습이 음성에 오다

2020년 Meta의 Wav2Vec 2.0은 "라벨 없는 음성 수만 시간으로 사전학습 → 적은 라벨로 파인튜닝"을 가능케 했습니다. BERT가 텍스트에서 한 일을 음성에서 한 셈입니다. HuBERT, WavLM도 같은 흐름.

  • 마스킹: 음성의 일부 구간을 마스킹하고 그 구간의 "양자화된 코드"를 맞추도록 학습
  • 효과: 라벨 10시간만 있어도 1,000시간으로 학습한 전통 모델에 필적
  • 저자원 언어(한국어 지역 방언 등)에서 특히 가치

Whisper — 다국어·robust ASR의 사실상 표준

2022년 OpenAI가 공개한 Whisper는 "웹에서 긁은 680,000시간 다국어 음성 + 전사 쌍"으로 지도학습한 Transformer encoder-decoder입니다. 공개 당시 "거의 모든 벤치마크에서 SOTA에 근접하면서 노이즈·억양에 강함"으로 충격을 줬습니다.

Whisper의 한계

  • 환각(hallucination): 침묵·배경음악 구간에서 없는 문장을 지어낼 때가 있다. VAD 전처리로 상당 부분 완화.
  • 화자 구분 안 됨: Diarization은 Whisper 밖에서(WhisperX, pyannote 등)
  • 스트리밍 아님: 기본은 배치. 실시간은 RNN-T 계열(Google USM, NVIDIA Parakeet)이 유리
  • 긴 문맥의 수치 오류: 금액·날짜의 숫자가 간혹 틀림 → LLM 후처리로 교정

TTS 변천사 — WaveNet에서 ElevenLabs까지

TTS(Text-to-Speech)는 로봇 같은 소리에서 사람 구별 어려운 수준까지 10년 안에 왔습니다.

음성 LLM — Pipeline에서 네이티브 Omni로

2024년 전까지 "음성 대화 AI"는 세 단계 파이프라인이었습니다: ASR → LLM → TTS. 각 단계가 수백 ms 걸려 전체 지연이 1.5~3초, 자연스러운 대화가 어려웠습니다. 2024년 5월 OpenAI의 GPT-4o가 이걸 뒤집었습니다.

주요 음성 LLM:

  • GPT-4o Realtime (2024): 232ms 평균 지연, 끼어들기 지원, 50+ 언어, 감정·웃음·속삭임까지 처리
  • Gemini Live (2024): Google, 영상+음성 동시, 스크린 공유도 가능
  • Claude Voice (2024): Anthropic, 모바일 앱 중심
  • Moshi (Kyutai, 2024): 7B 오픈소스 음성 모델, 로컬에서 실시간 대화
  • Qwen2-Audio: 알리바바, 오픈웨이트

금융권 음성 AI 체크리스트

  • 통화 녹취 법규: 자본시장법·전자금융감독규정상 트레이딩 콜은 보관 의무가 있지만, 전사·분석은 별도 동의 범위 확인 필요. 개인정보보호법에 따라 민감정보 마스킹 필수.
  • Deepfake Voice 사기 급증: 2024년부터 "임원 음성 복제 송금 지시" 사기 사례. 음성만으로는 지시 실행 절대 금지, 2중 채널(IM·공식 시스템) 검증 의무.
  • 성문인증은 보조 수단: 단독 인증 금지, 비밀번호·OTP와 조합(2FA).
  • Whisper 환각: 침묵·배경음악 구간에서 거짓 문장 생성 가능. 금융 수치가 포함된 전사는 반드시 사람 검토 또는 LLM 교차 검증.
  • 저작권·초상권: 복제 음성 생성(VALL-E, ElevenLabs)은 본인 동의 없이 사용 금지.
  • 데이터 유출: 녹취는 공개 API에 올리지 말고 사내 Whisper 서버 운영. 다수의 금융사가 사내 GPU 서버에 self-hosted Whisper를 선호.

예제 40-1 — 콜녹취 분석 설계 난이도 ★★☆

지점 콜센터 하루 10,000건의 통화 녹음에서 "민원·불만 가능성이 높은 통화만 사람 검토용으로 선별"하는 파이프라인을 설계하세요. GPU 자원은 제한적입니다.

정답과 해설 보기
  1. 프리필터 (CPU): 녹음 길이 >1분, 특정 키워드(음성 활성 감지만으로는 부족), 또는 음성 중 "강한 톤 변화" 구간이 있는 통화만 다음 단계로. 10,000건 → 3,000건.
  2. Whisper tiny/base로 1차 전사: CPU에서도 실시간보다 빠름. 전체 전사 아니라 처음·마지막 2분 샘플링.
  3. LLM 소형 모델로 1차 분류: Llama 3.2 3B / Qwen2.5 7B 로컬 → "민원 가능성 0~1". 상위 500건으로 압축.
  4. Whisper large-v3-turbo + 화자 분리로 완전 전사: 500건만. GPU 1장이면 몇 시간.
  5. 프런티어 LLM으로 상세 분석: Claude Opus 또는 GPT-5로 "쟁점·조치안·에스컬레이션 여부" 보고서. 사람 상담관리자가 최종 검토.

핵심: "큰 모델을 전부에 돌리지 말고" 작은 모델로 10,000 → 500으로 거르고, 큰 모델은 그 500건에만. 비용 20배 절감 + 전체 지연 2시간 이내.

핵심 정리

  • 음성은 보통 멜 스펙트로그램(100 fps × 80 bin)으로 바꿔 모델에 입력. MFCC는 전통 시대의 유산.
  • HMM-GMM 시대(1980~2010) → DNN-HMM(2012) → End-to-End(CTC·RNN-T·Attention).
  • CTC는 간단·빠름(Deep Speech), RNN-T는 스트리밍 가능(Siri·Google), Attention은 고품질 배치(Whisper).
  • Wav2Vec 2.0·HuBERT가 "라벨 없는 수만 시간" 사전학습을 가능케 함. 저자원 언어의 구원자.
  • Whisper(2022)는 다국어·robust ASR의 사실상 표준. large-v3-turbo로 속도까지 확보(2024).
  • Whisper 한계: 침묵 환각, 화자 분리 안 됨, 스트리밍 X. VAD·pyannote·LLM 후처리로 보완.
  • TTS: WaveNet(2016) → Tacotron 2 → FastSpeech → VITS → Diffusion TTS → ElevenLabs·GPT-4o Voice.
  • 음성 대화: 전통 pipeline(ASR→LLM→TTS, 지연 1.5~3s) → 네이티브 omni(GPT-4o 232ms, Gemini Live).
  • 금융/OMS: 실적콜 분석, 콜센터 녹취, 리서치 회의록, 성문인증, OMS 야간 음성 알림.
  • 체크리스트: 녹취 법규·Deepfake Voice 방어·성문인증은 2FA 보조·Whisper 환각 교차검증·사내 self-hosted 선호.

면접 질문

자주 나오는 질문

Q1. CTC·RNN-T·Attention의 차이를 설명해 주세요.

셋 다 end-to-end ASR입니다. (1) CTC는 인코더만으로 프레임별 토큰 확률을 뽑고 blank 토큰으로 정렬을 학습. 간단·빠르지만 출력 간 조건부 독립 가정이 있어 언어모델 결합이 필요. Deep Speech 2가 대표. (2) RNN-T는 인코더 + 예측기(언어 모델) + 결합기 구조로 출력 간 의존성을 모델링하면서도 스트리밍이 가능. Siri·Google Assistant가 쓴다. (3) Attention(인코더-디코더)는 번역처럼 전체 음성을 보고 디코더가 토큰을 생성. 성능이 가장 좋지만 전체를 들어야 해 스트리밍이 어려움. Whisper가 대표.

Q2. Whisper는 왜 그렇게 로버스트한가요?

세 가지 때문입니다. (1) 데이터 다양성: 68만 시간의 다국어·다환경 데이터로 학습 → 노이즈·억양·전문용어에 강함. (2) Multitask 학습: 전사·번역·언어감지·타임스탬프를 한 모델이 토큰 포맷(prompt)으로 지시받아 수행 → 다용도. (3) Transformer 인코더-디코더: 어텐션으로 긴 문맥을 참고해 숫자·고유명사 복원. 한계는 침묵 구간 환각과 스트리밍 불가.

Q3. 전통 pipeline(ASR→LLM→TTS)과 GPT-4o 같은 네이티브 음성 LLM의 차이는?

Pipeline은 세 모델이 분리되어 (1) 지연이 1.5~3초로 자연 대화 어려움, (2) 억양·웃음·강조·끼어들기가 ASR 단계에서 소실, (3) 각 단계 환각·오류가 누적됩니다. 네이티브 omni(GPT-4o, Gemini Live)는 음성 자체를 토큰화해 LLM이 음성 입출력을 직접 처리 → 232ms 지연, 억양·감정 유지, 끼어들기 자연스러움. 단점은 (a) 아직 외부 공개가 제한적, (b) 데이터·규제 측면 통제가 pipeline보다 어려움. 민감 분야에선 pipeline이 여전히 유리.

Q4. 금융권에서 Whisper 쓸 때 가장 조심할 점은?

(1) 녹취 법적 처리: 통화 녹취는 보관 의무가 있지만 전사·분석은 범위 확인·동의 필요. (2) 민감정보 마스킹: 전사 결과에서 계좌번호·주민번호 자동 마스킹. (3) 침묵 환각: Whisper가 침묵에서 "감사합니다" 같은 거짓 문장을 지어낼 수 있음 → VAD·word timestamps로 필터링. (4) 숫자 오류: 금액·날짜의 자릿수 실수 → LLM 교차검증 또는 사람 검토. (5) 사내 self-hosted: 민감 녹취를 공개 API에 보내지 말 것. (6) Deepfake 방어: 음성만으로 지시 실행 절대 금지, 2중 채널 검증 의무.

Q5. OMS 운영자가 음성 AI로 할 수 있는 가장 가치 있는 일은?

세 가지입니다. (1) 야간 당직 음성 알림: LLM이 요약한 장애 정보를 TTS로 담당자에게 전화 발신 → "뭐가 터졌고 무슨 조치가 필요한지" 2문장으로. 바로 깨어도 상황 파악. (2) 실적 발표 콜 자동 전사·요약: 영문 콜 녹음 → Whisper → LLM 요약 → OMS 알림. 리서치팀과 공유. (3) 민원·분쟁 녹취 1차 분류: 거래 분쟁 통화에서 쟁점·시각·금액을 자동 추출해 분쟁처리팀에 전달. 모두 "사람 결정 전 1차 가공". 자동 집행 금지는 LLM/비전과 동일.
