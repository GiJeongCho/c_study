배열과 포인터

C에서 배열과 포인터는 쌍둥이처럼 붙어 다닙니다. 배열 이름은 대부분의 상황에서 첫 요소의 주소로 바뀌고, arr[i]라는 익숙한 표기도 사실은 포인터 연산의 줄임말입니다. 이 관계를 정확히 알아야 거래 금액 배열을 함수로 넘기고, 합계·평균·최댓값을 구하고, 배열 길이를 잃어버려 생기는 버퍼 오버런을 막을 수 있습니다.

이 장에서 배울 것

  • 배열 이름이 첫 요소의 주소로 변환(decay)되는 규칙과 그 예외 3가지를 압니다.
  • arr[i]가 *(arr + i)와 완전히 같은 이유를 포인터 연산으로 설명합니다.
  • 배열 이름과 포인터 변수의 차이(sizeof, 대입 가능 여부, 메모리 존재 여부)를 구분합니다.
  • arr와 &arr의 값은 같지만 자료형이 다르다는 것을 이해합니다.
  • 배열 매개변수가 실제로는 포인터라는 사실과, 그래서 길이를 따로 넘겨야 하는 이유를 압니다.
  • const 매개변수를 이용해 합계·평균·최댓값·역순 함수를 작성하고 거래 금액 배열을 처리합니다.

10-1배열과 포인터의 관계

8장에서 배열을 "같은 자료형의 변수를 연속으로 여러 개 만드는 방법"으로 배웠고, 9장에서 포인터를 "주소를 저장하는 변수"로 배웠습니다. 이 둘은 따로 노는 개념이 아닙니다. 배열은 메모리에 빈틈없이 연속으로 놓이고, 포인터 연산은 자료형 크기 단위로 이동합니다. 이 두 성질이 맞물리면서, C에서 배열을 다루는 모든 문법이 포인터 연산 위에 세워져 있습니다.

배열 이름은 첫 번째 요소의 주소

먼저 실험부터 해 봅시다. 배열 이름을 주소처럼 출력하면 무엇이 나올까요?

배열 이름 arr를 식에 쓰면 첫 요소의 주소 &arr[0]와 같은 값이 됩니다. 그래서 *arr는 첫 요소이고, *(arr + 3)은 9장의 포인터 연산 규칙에 따라 3 × 4 = 12바이트 뒤의 요소, 즉 arr[3]입니다.

왜 배열 이름이 주소로 바뀔까? — 배열의 "decay" 규칙

C 표준에는 이런 규칙이 있습니다. "배열형 표현식은, 아래의 예외를 제외하고, 그 배열의 첫 요소를 가리키는 포인터로 변환된다." 이 변환을 흔히 decay(붕괴, 퇴화)라고 부릅니다. int arr[5]의 자료형은 "int 5개짜리 배열"(int [5])이지만, 식에 쓰는 순간 대부분 int *형 값 &arr[0]으로 바뀝니다.

이렇게 설계한 이유는 C의 조상인 B 언어와 BCPL에 있습니다. 그 언어들에서 배열 이름은 실제로 첫 요소의 주소를 담은 포인터 변수였습니다. C를 만든 데니스 리치는 구조체 안에 배열을 넣기 위해 "배열 이름에 해당하는 포인터를 메모리에 따로 두지 않는" 방식으로 바꾸면서도, 기존 코드의 *(arr + i) 표기가 그대로 동작하도록 "식에 쓰면 주소로 바뀐다"는 규칙을 만들었습니다. 덕분에 큰 배열을 함수에 넘길 때 통째로 복사하지 않고 주소 하나만 넘기는 효율도 얻었습니다.

decay가 일어나지 않는 3가지 예외

  1. sizeof arr: 배열 전체의 크기(20)를 돌려줍니다. 포인터 크기(8)가 아닙니다.
  2. &arr: "배열 전체"의 주소가 됩니다. 자료형이 int (*)[5]입니다(10-1-5).
  3. 문자열 리터럴로 char 배열을 초기화할 때: char s[] = "KRW";에서 "KRW"는 주소로 바뀌지 않고 4바이트가 그대로 배열에 복사됩니다(12장).

(C11에는 _Alignof도 언급되지만 실무에서 신경 쓸 일은 거의 없습니다.) 이 세 경우를 빼면, 배열 이름은 "첫 요소의 주소"라고 생각해도 됩니다.

arr[i]와 *(arr + i)는 완전히 같다

C 표준은 대괄호 연산자를 이렇게 정의합니다. "E1[E2]는 (*((E1) + (E2)))와 같다." 즉 arr[i]는 컴파일러가 *(arr + i)로 바꿔서 처리하는 문법적 편의(syntactic sugar)일 뿐입니다. 순서를 따라가 보면 다음과 같습니다.

  1. arr가 decay되어 첫 요소의 주소(1000)가 됩니다.
  2. arr + i는 포인터 연산이므로 1000 + i × sizeof(int) 주소가 됩니다. i=3이면 1012.
  3. *로 그 주소의 int를 꺼냅니다. → 40

3[arr]가 왜 동작할까?

3[arr]는 정의에 따라 *(3 + arr)이고, 덧셈은 교환법칙이 성립하므로 *(arr + 3)과 같습니다. 이 기묘한 표기가 동작한다는 사실은 "대괄호가 배열만의 특별한 문법이 아니라 포인터 덧셈 + 간접 참조의 줄임말"이라는 강력한 증거입니다. 면접에서 개념 확인용으로 가끔 나오지만, 실제 코드에 쓰면 동료에게 미움받으니 절대 쓰지 마세요.

또 하나 중요한 결과: 포인터 변수에도 대괄호를 쓸 수 있습니다(p[i]). 대괄호는 "주소 + 정수"만 있으면 되기 때문입니다. 그래서 함수가 배열을 포인터로 받아도 a[i]처럼 자연스럽게 쓸 수 있는 것입니다.

배열 인덱스가 0부터 시작하는 이유

arr[i]가 *(arr + i)이므로, 첫 요소는 "시작 주소에서 0칸 떨어진 곳"이라 arr[0]입니다. 인덱스는 "몇 번째"가 아니라 "시작점으로부터의 거리(오프셋)"입니다. 1부터 시작한다면 매번 arr + (i - 1)을 계산해야 하므로 뺄셈이 한 번 더 필요합니다. 그래서 C와 그 후손 언어(C++, Java, C#, Python 등) 대부분이 0부터 셉니다.

예제 10-1 난이도 ★☆☆

long long fee[4] = {500, 1000, 1500, 0};에서 fee[0]의 주소가 3000이라면 (1) fee + 2의 값, (2) *(fee + 1), (3) *fee + 1, (4) &fee[3] - fee를 구하세요.

정답과 해설 보기

(1) long long은 8바이트이므로 3000 + 2×8 = 3016. (2) fee[1] = 1000. (3) (*fee) + 1 = 500 + 1 = 501 — 괄호가 없으면 값에 1을 더합니다. (4) 같은 배열 안의 포인터 뺄셈은 요소 개수이므로 3입니다(바이트 차이 24가 아님).

포인터 변수로 배열 순회하기

배열 이름은 첫 요소의 주소이므로 포인터 변수에 그대로 대입할 수 있습니다(int *p = arr;). 그 다음에는 두 가지 순회 방식이 가능합니다. 인덱스를 늘리는 방식과, 포인터 자체를 한 칸씩 옮기는 방식입니다.

어느 방식이 더 빠를까?

과거 최적화가 약한 컴파일러 시절에는 amt[i]가 매번 "시작 주소 + i × 8"을 계산해야 해서 포인터 이동 방식이 빠르다고 여겨졌습니다. 하지만 현대 gcc·clang은 -O2에서 두 코드를 거의 같은 기계어로 만듭니다(x86의 주소 지정 방식 [base + index*8]이 곱셈을 공짜로 해 주기 때문). 따라서 성능보다 읽기 쉬운 쪽을 고르면 됩니다. 일반적인 업무 코드에서는 인덱스 방식이 실수가 적고, 문자열 처리처럼 "끝 표시를 만날 때까지 전진"하는 코드는 포인터 방식이 자연스럽습니다.

배열 이름과 포인터 변수의 차이

지금까지 보면 배열 이름과 포인터 변수가 똑같아 보입니다. 하지만 배열은 포인터가 아닙니다. 결정적인 차이 세 가지를 실험으로 확인해 봅시다.

왜 arr = other; 는 안 될까?

배열 이름 arr는 "주소를 담고 있는 변수"가 아니기 때문입니다. 컴파일러 입장에서 arr는 "스택 프레임 기준 -32바이트 위치에서 시작하는 20바이트"라는 고정된 위치일 뿐이고, 그 주소를 따로 저장해 둔 칸이 없습니다. 바꿀 칸이 없으니 대입도, 증가도 할 수 없습니다. 반면 p는 8바이트 칸을 갖고 있어서 그 칸의 내용을 바꿀 수 있습니다.

그렇다면 "배열 전체를 복사"하고 싶다면? 대입 연산자로는 불가능하므로 반복문으로 요소를 하나씩 복사하거나 memcpy(arr, other, sizeof arr);를 씁니다. (흥미롭게도 배열을 구조체 안에 넣으면 구조체 대입으로 통째 복사가 됩니다. 15장 이후에서 다룹니다.)

자주 하는 실수 — "배열은 포인터다"라고 외우기

"배열 이름은 상수 포인터다"라는 설명을 자주 보지만 정확하지 않습니다. 상수 포인터(int *const)라면 sizeof가 8이어야 하고 &를 붙이면 int *const *가 되어야 하는데 실제로는 20과 int (*)[5]입니다. 정확한 표현은 "배열은 배열이고, 대부분의 식에서 첫 요소를 가리키는 포인터 값으로 변환된다"입니다. 다른 소스 파일에 extern int *arr;로 잘못 선언하면 링크는 되지만 배열의 첫 8바이트를 주소로 해석해 바로 segfault가 나는 고전적 버그도 이 차이에서 생깁니다.

&arr와 arr — 값은 같고 자료형은 다르다

&arr는 decay의 예외입니다. "배열 전체의 주소"를 뜻하고, 자료형은 "int 5개짜리 배열을 가리키는 포인터", 즉 int (*)[5]입니다. 배열 전체가 시작하는 곳과 첫 요소가 시작하는 곳은 같은 위치이므로 주소값은 같습니다. 하지만 자료형이 다르므로 +1 했을 때 이동하는 거리가 다릅니다.

왜 이런 구분이 필요할까? — 2차원 배열의 열쇠

int (*)[5] 같은 배열 포인터는 혼자서는 쓸 일이 드물지만, 2차원 배열에서 핵심 역할을 합니다. int m[3][5];는 "int[5]짜리 배열 3개"이므로, m을 식에 쓰면 첫 요소, 즉 첫 행 전체의 주소로 decay되며 자료형은 int (*)[5]입니다. 그래서 m + 1은 20바이트 뒤인 둘째 행을 가리키고, m[i][j] == *(*(m + i) + j)가 성립합니다. 2차원 배열을 함수에 넘길 때 void f(int m[][5], int rows)처럼 열 크기는 반드시 써야 하는 이유도 이것입니다. 컴파일러가 "한 행이 몇 바이트인가"를 알아야 m + i를 계산할 수 있기 때문입니다.

괄호 위치에 주의하세요. int (*pa)[5]는 "int 5개 배열을 가리키는 포인터 하나"이고, int *pa[5]는 "int 포인터 5개짜리 배열"(포인터 배열)입니다. 대괄호가 *보다 우선순위가 높기 때문에 괄호로 묶어야 포인터가 먼저 결합합니다.

예제 10-2 난이도 ★★☆

double r[4];의 r[0] 주소가 5000일 때 다음 값을 구하세요. (1) r + 1 (2) &r + 1 (3) &r[0] + 1 (4) sizeof r (5) sizeof &r (6) sizeof *&r

정답과 해설 보기
  1. 5008 — r이 double *로 decay, 한 칸 8바이트.
  2. 5032 — &r은 double (*)[4], 한 칸이 4×8 = 32바이트.
  3. 5008 — &r[0]은 double *.
  4. 32 — sizeof는 decay 예외, 배열 전체 크기.
  5. 8 — &r은 포인터이므로 포인터 크기.
  6. 32 — *&r은 배열 r 그 자체이므로 배열 크기.

은행 시스템에서는 — 고정 길이 레코드 배열과 오프셋

일마감 배치 프로그램은 하루치 거래 파일(수십만~수백만 건)을 읽어 원장에 반영합니다. 이 파일은 흔히 "한 레코드 = 고정 200바이트"처럼 고정 길이 레코드의 연속입니다. 파일을 메모리에 한꺼번에 올려 두면 그 자체가 거대한 배열이 되고, n번째 레코드의 시작 위치는 base + n * 200입니다. 이것이 정확히 arr[n] == *(arr + n)의 원리입니다. 레코드를 구조체로 정의하고 struct trx_rec *rec = (struct trx_rec *)buf;처럼 포인터를 씌우면 rec[n].amount로 바로 접근할 수 있습니다(구조체와 패딩은 이후 장에서). 반대로 레코드 길이 계산이 1바이트만 틀려도 그 뒤 모든 레코드가 밀려 읽히는 대형 장애가 되므로, 실무에서는 레코드 길이를 매크로 상수 하나로 관리하고 파일 크기가 레코드 길이의 배수인지부터 검증합니다.

10-2배열을 처리하는 함수

실무 프로그램에서 배열은 거의 항상 함수로 넘겨져 처리됩니다. 하루치 거래 금액 배열을 받아 합계를 내는 함수, 계좌 잔액 배열에서 최댓값을 찾는 함수처럼 말입니다. 그런데 배열을 함수로 넘기는 순간 앞 절의 decay 규칙이 작동하면서, 초보자가 예상하지 못한 일들이 일어납니다. 이 절에서는 그 원리와 올바른 함수 설계 방법을 다룹니다.

배열 매개변수는 사실 포인터다

함수 매개변수를 배열처럼 선언할 수 있습니다. 그러나 컴파일러는 이것을 포인터로 바꿔서 처리합니다. 다음 세 선언은 완전히 같습니다.

정말 그런지 sizeof로 확인해 봅시다.

왜 배열은 통째로 복사되지 않을까?

함수 호출의 인자 자리에 arr를 쓰는 순간, 그것은 "식"이므로 decay 규칙이 적용되어 &arr[0]이라는 주소값이 됩니다. C의 인자 전달은 값 복사이므로 이 주소값 8바이트가 복사됩니다. 결과적으로 함수는 원본 배열을 가리키는 포인터를 받게 됩니다.

이 설계의 장점은 효율입니다. 100만 건짜리 거래 금액 배열(8MB)을 함수를 부를 때마다 복사한다면 성능이 끔찍하겠지요. 단점은 두 가지입니다. ① 함수가 원본을 수정할 수 있으므로 의도치 않은 변경 위험이 있고(→ const로 해결), ② 배열의 길이 정보가 사라집니다(→ 길이를 따로 넘겨서 해결).

자주 하는 실수 — 함수 안에서 sizeof로 길이 구하기

a는 포인터이므로 sizeof a는 8이고, 64비트에서 long long 배열이면 항상 1, int 배열이면 항상 2가 나옵니다. 테스트 데이터가 우연히 1~2개면 통과해 버려서 운영에서야 발견되는 무서운 버그입니다. sizeof arr / sizeof arr[0] 공식은 배열이 선언된 바로 그 범위에서만 유효합니다.

배열의 길이를 함께 전달해야 하는 이유

함수가 받은 것은 "시작 주소" 하나뿐입니다. 어디서 끝나는지는 알 길이 없습니다. 그래서 C에서는 다음 세 가지 방법 중 하나로 끝을 알려 줍니다.

방법예장단점
① 길이를 매개변수로sum(const long long *a, size_t n)가장 일반적이고 명확함. 호출자가 정확한 n을 넘길 책임
② 끝 표시(sentinel) 값문자열의 '\0', 금액 배열 끝에 -1길이를 안 넘겨도 되지만, 끝 표시가 빠지면 끝없이 읽음. 끝 표시 값이 정상 데이터로 나오면 안 됨
③ 시작·끝 포인터sum(const long long *first, const long long *last)범위를 반열림 구간 [first, last)로 표현. C++ STL 방식

"시작 주소 + 길이" 설계가 주는 유연성

마지막 두 줄을 보세요. sum(wd + 2, 2)는 "wd의 세 번째 요소부터 2개"를 더합니다. 함수가 받는 것이 "주소와 개수"이기 때문에 배열의 일부 구간을 자유롭게 넘길 수 있습니다. 이것이 C의 memcpy(dst, src, n), fwrite(buf, size, n, fp), qsort(base, n, size, cmp) 같은 표준 함수가 모두 "포인터 + 길이" 형태인 이유입니다. 다른 언어의 슬라이스(slice)가 하는 일을 C는 포인터 연산으로 해냅니다.

길이에 size_t를 쓴 것도 눈여겨보세요. size_t는 sizeof의 결과형이자 "메모리상 객체 크기를 표현할 수 있는 부호 없는 정수"로, 64비트에서 8바이트입니다. 다만 부호가 없으므로 for (i = n - 1; i >= 0; i--)처럼 거꾸로 세면 i가 0에서 1 줄 때 최댓값으로 넘어가 무한 루프가 되는 함정이 있습니다.

C99의 배열 매개변수 표기 — static과 VLA

C99부터는 void f(size_t n, const long long a[static n])처럼 쓸 수 있습니다. static n은 "최소 n개 요소가 있는 유효한 배열을 넘긴다(NULL 아님)"는 약속을 컴파일러에게 알려 최적화와 경고에 활용하게 합니다. 또 a[n]처럼 앞선 매개변수를 길이로 쓰는 것을 가변 길이 배열(VLA) 표기라고 하는데, 여전히 a는 포인터이고 sizeof는 8입니다. 문서화 효과는 있지만 길이 매개변수의 필요성은 그대로입니다. MSVC는 VLA를 지원하지 않으므로 이식성이 필요한 금융권 코드에서는 잘 쓰지 않습니다.

const 매개변수로 원본 보호하기

배열은 주소로 넘어가므로 함수가 원본을 바꿀 수 있습니다. 합계 함수처럼 읽기만 하는 함수에 실수로 a[i] = 0; 같은 코드가 들어가면 호출자의 데이터가 망가집니다. 그래서 읽기 전용 배열 매개변수에는 반드시 const를 붙입니다.

const는 문서이자 계약입니다

함수 원형 long long sum(const long long *a, size_t n);만 보고도 호출자는 "이 함수는 내 배열을 바꾸지 않는다"는 것을 압니다. 원형이 long long *a라면 "혹시 바꾸나?" 의심하며 구현을 열어 봐야 합니다. 대형 금융 시스템처럼 수백 명이 함께 만드는 코드에서는 이 차이가 엄청납니다. 원칙: 수정할 이유가 없는 포인터 매개변수에는 전부 const를 붙인다.

합계·평균·최댓값·최솟값 함수

이제 배열 처리의 기본 함수 세트를 만들어 봅시다. 거래 금액 배열을 예로 듭니다.

왜 값이 아니라 인덱스나 포인터를 반환할까?

"최댓값이 87,000원"이라는 정보만으로는 어느 거래였는지 알 수 없습니다. 같은 금액의 거래가 여러 건일 수도 있고, 그 거래의 시각이나 계좌번호를 함께 출력하려면 위치가 필요합니다. 인덱스를 반환하면 다른 병렬 배열(거래 시각 배열, 계좌번호 배열)에서도 같은 위치를 찾을 수 있고, 포인터를 반환하면 그 요소를 바로 읽거나 (const가 아니라면) 수정할 수 있습니다. pmin - amt처럼 포인터 뺄셈으로 인덱스를 되찾을 수도 있습니다.

평균 계산도 주의 깊게 보세요. 172,000 / 6은 28,666.666...입니다. 정수 나눗셈은 소수점 이하를 버리므로 28,666, 반올림 공식 (합 + n/2) / n은 28,667이 됩니다. 금융 업무에서는 "원 미만 절사"인지 "반올림"인지가 상품 약관에 정해져 있으므로, 어느 방식을 쓰는지 코드에 명확히 드러내야 합니다. (음수 금액이 섞이면 반올림 공식이 달라져야 한다는 점도 기억해 두세요.)

자주 하는 실수 — 빈 배열과 최댓값 초기값

최댓값을 구할 때 long long max = 0;으로 시작하면, 모든 값이 음수인 배열(예: 출금만 있는 거래 배열을 음수로 표현)에서 결과가 0이 되어 틀립니다. 첫 요소로 초기화하는 것이 정석입니다. 대신 그러려면 n이 0이 아니어야 하므로, 호출 전에 n > 0을 보장하거나 함수 안에서 검사해야 합니다. 위 index_of_max는 n이 0이면 0을 반환하는데, 호출자가 amt[0]을 읽으면 범위 밖 접근이 됩니다. 실무 코드라면 반환형을 int로 하고 빈 배열일 때 -1을 반환하는 식으로 방어합니다.

예제 10-3 난이도 ★★☆

배열에서 특정 금액 이상인 거래의 개수를 세는 함수 size_t count_over(const long long *a, size_t n, long long limit)를 작성하세요. {12000, 5000, 87000, 3000, 45000, 20000}에서 limit = 20000이면 결과는?

정답과 해설 보기

87000, 45000, 20000이 20000 이상이므로 3입니다. "이상"이므로 >=를 써야 20000이 포함됩니다. 경계값(20000)을 포함하는지는 요구사항에서 꼭 확인해야 하는 부분입니다("초과"라면 2).

배열을 역순으로 뒤집는 함수

배열을 제자리에서(in-place, 추가 배열 없이) 뒤집으려면 양 끝에서 하나씩 맞바꾸며 가운데로 모이면 됩니다. 9장의 swap을 그대로 활용할 수 있습니다.

왜 n < 2 검사가 필요할까?

n이 size_t(부호 없음)이므로 n이 0일 때 a + n - 1은 a - 1이 되고, 이는 배열 시작 전 위치라 계산만으로도 UB입니다. 또 n - 1을 별도로 계산하면 0 - 1이 아주 큰 수(18446744073709551615)로 바뀌는 언더플로가 납니다. 경계 조건(0개, 1개)을 먼저 처리하는 습관이 이런 함정을 막습니다. 짝수 개, 홀수 개 모두 left < right 조건 하나로 깔끔하게 끝난다는 점도 이 알고리즘의 장점입니다.

예제 10-4 난이도 ★★☆

배열 src의 내용을 역순으로 다른 배열 dst에 복사하는 함수 void reverse_copy(int *dst, const int *src, size_t n)를 작성하세요. 원본은 바뀌지 않아야 합니다.

정답과 해설 보기

src에 const를 붙여 원본 보호를 컴파일러가 보장하게 합니다. dst[i]에는 src의 뒤에서 i번째, 즉 src[n - 1 - i]를 넣습니다.

주의: dst와 src가 같은 배열이면(겹치면) 앞쪽을 덮어쓰면서 뒤쪽 원본이 망가집니다. 그런 경우를 허용하지 않는다면 C99의 restrict 한정자(int *restrict dst, const int *restrict src)로 "겹치지 않는다"는 약속을 표시할 수 있습니다. 표준 함수 memcpy(겹침 불가)와 memmove(겹침 허용)의 차이도 바로 이것입니다.

금융 예제 — 거래 금액 배열 처리

하루 동안 한 계좌에서 발생한 거래를 배열로 받아 일일 거래 요약을 만드는 프로그램입니다. 입금은 양수, 출금은 음수로 표현합니다.

  1. 입금 합계와 출금 합계를 한 번의 순회로 구해 출력 매개변수로 돌려줍니다.
  2. 가장 큰 출금(가장 작은 음수)의 위치를 찾습니다.
  3. 절댓값 1,000만 원 이상인 고액 거래 건수를 셉니다.
  4. 시작 잔액에 거래를 순서대로 반영하면서 하루 중 최저 잔액을 구합니다.

결과 검증 — 손으로 따라가 보기

입금: 3,500,000 + 150,000 + 10,500,000 = 14,150,000원. 출금: 45,000 + 320,000 + 12,000,000 + 8,000 + 1,500,000 = 13,873,000원. 잔액 흐름: 20,000,000 → 23,500,000 → 23,455,000 → 23,135,000 → 11,135,000 → 11,285,000 → 11,277,000 → 9,777,000(최저) → 20,277,000(최종). 고액 거래는 -12,000,000과 10,500,000 두 건입니다.

함수 설계에서 주목할 점: 모든 조회 함수가 const long long *를 받으므로 거래 배열은 어떤 함수에서도 바뀌지 않습니다. 결과가 둘 이상인 함수(sum_by_sign, apply_all)는 9장의 출력 매개변수 패턴을 씁니다. "출금 없음"을 -1로 표시하기 위해 인덱스를 int로 반환한 것도 의도된 설계입니다.

은행 시스템에서는 — 고액 현금거래 보고와 일마감 집계

국내 금융회사는 일정 금액(현금 기준 1천만 원) 이상의 거래를 금융정보분석원에 보고하는 고액현금거래보고(CTR) 의무가 있고, 짧은 기간에 기준 바로 아래 금액으로 나누어 거래하는 "분할 거래"도 이상 거래 탐지 대상이 됩니다. 이런 집계는 대개 야간 일마감 배치에서 계좌별 거래 배열을 순회하며 이루어집니다. 위 예제의 count_large, sum_by_sign이 실제 배치 로직의 뼈대와 같습니다. 실무에서 추가로 신경 쓰는 점은 ① 합계가 long long 범위를 넘지 않는지(법인 계좌는 하루 수조 원도 흐름), ② 배열 길이를 파일 건수와 대조하는 건수·금액 검증(컨트롤 토털), ③ 기준 금액을 코드에 박지 않고 매개변수 테이블에서 읽어 오는 것입니다. 규정이 바뀔 때 소스를 고쳐 재배포하지 않아도 되도록 말입니다.

2차원 배열을 함수에 넘길 때

지점별·월별 거래 금액처럼 2차원 배열 long long tbl[3][12]를 넘길 때는 void f(long long t[][12], size_t rows) 또는 같은 의미인 void f(long long (*t)[12], size_t rows)로 받습니다. 10-1-5에서 본 것처럼 tbl이 "12개짜리 행"을 가리키는 포인터로 decay되기 때문입니다. 열 개수 12는 자료형의 일부이므로 생략할 수 없고, 행 개수는 1차원 배열의 길이처럼 따로 넘겨야 합니다. long long **t로 받으면 자료형이 맞지 않아 경고가 나고 실행하면 엉뚱한 주소를 읽습니다. 2차원 배열은 "포인터의 배열"이 아니라 "배열의 배열"이기 때문입니다.

핵심 정리

  • 배열 이름은 식 안에서 첫 요소의 주소(&arr[0])로 변환(decay)됩니다. 예외는 sizeof arr, &arr, 문자열 리터럴로 char 배열 초기화 세 가지입니다.
  • arr[i]는 표준에서 *(arr + i)로 정의됩니다. 그래서 포인터 변수에도 p[i]를 쓸 수 있고, 인덱스는 시작점으로부터의 거리라 0부터 시작합니다.
  • 배열은 포인터가 아닙니다. 배열 이름에는 주소를 담는 칸이 없으므로 대입·증가가 불가하고, sizeof는 배열 전체 크기를 돌려줍니다.
  • arr와 &arr는 값이 같지만 자료형이 int *와 int (*)[5]로 달라서 +1의 이동 거리가 요소 하나와 배열 전체로 다릅니다. 이 원리가 2차원 배열의 기반입니다.
  • 함수의 배열 매개변수 T a[]는 T *a와 같습니다. 배열은 주소만 복사되어 넘어가므로 함수가 원본을 수정할 수 있고, 길이 정보는 사라집니다.
  • 함수 안에서 sizeof a / sizeof a[0]는 길이가 아닙니다. 길이는 size_t n으로 따로 넘기거나, 끝 표시 값 또는 시작·끝 포인터를 사용합니다.
  • 읽기만 하는 배열 매개변수에는 const T *를 붙여 원본 보호를 컴파일러가 강제하게 합니다.
  • 최댓값·최솟값 함수는 값보다 인덱스나 포인터를 반환하면 위치 정보까지 얻을 수 있습니다. 초기값은 첫 요소로 하고 빈 배열을 방어합니다.
  • 제자리 뒤집기는 양 끝 두 포인터를 교환하며 가운데로 모으는 방식이며, n이 0·1일 때를 먼저 처리해야 부호 없는 언더플로와 범위 밖 계산을 피합니다.
  • 금융 집계 함수는 const 입력 배열 + 출력 매개변수 + 정수(원 단위) 연산 + 명시적 반올림 규칙으로 작성합니다.

이 장에서 나오는 면접 질문

Q1. 배열과 포인터의 차이는 무엇인가요?

배열은 같은 자료형 요소들이 연속으로 놓인 메모리 덩어리 자체이고, 포인터는 주소 하나를 저장하는 독립된 변수입니다. 배열 이름은 대부분의 식에서 첫 요소의 주소로 변환되기 때문에 비슷해 보이지만, sizeof를 하면 배열은 전체 크기, 포인터는 8바이트(64비트)가 나오고, 배열 이름에는 대입이나 증가를 할 수 없으며, &를 붙였을 때 자료형도 다릅니다. 또 포인터는 자기 자신을 위한 저장 공간이 따로 있지만, 배열 이름에는 주소를 담는 공간이 없습니다.

꼬리 질문: "그럼 배열 이름은 상수 포인터인가요?" → 정확하지 않으며, 상수 포인터라면 sizeof가 8이어야 한다는 점을 근거로 들어 "배열이 포인터로 decay되는 것"이라고 설명합니다.

Q2. arr[i]는 내부적으로 어떻게 동작하나요?

C 표준은 arr[i]를 *(arr + i)로 정의합니다. arr가 첫 요소의 주소로 변환되고, 포인터 연산에 따라 i × sizeof(요소)바이트 뒤의 주소가 계산된 뒤, 그 주소를 역참조합니다. 덧셈은 교환법칙이 성립하므로 i[arr]도 같은 의미로 동작합니다. 이 때문에 배열 인덱스는 0부터 시작하며, 범위 검사는 전혀 하지 않습니다.

Q3. 배열을 함수에 전달하면 무엇이 전달되나요? 함수 안에서 sizeof를 하면?

배열 전체가 복사되지 않고 첫 요소의 주소가 값으로 전달됩니다. 매개변수를 int a[]나 int a[10]으로 써도 컴파일러는 int *a로 취급합니다. 따라서 함수 안에서 sizeof a는 포인터 크기인 8이 나오고, 배열의 길이는 알 수 없으므로 길이를 별도 매개변수로 넘겨야 합니다. 또 원본 주소가 넘어가므로 함수가 원본을 수정할 수 있어, 읽기 전용이면 const를 붙입니다.

Q4. arr와 &arr의 차이는 무엇인가요?

둘 다 같은 주소값을 갖지만 자료형이 다릅니다. int arr[5]에서 arr는 int *로 변환되어 +1하면 4바이트 이동하고, &arr는 int (*)[5], 즉 배열 전체를 가리키는 포인터라서 +1하면 20바이트 이동합니다. 이 배열 포인터 개념이 2차원 배열의 행 단위 이동과 2차원 배열을 함수로 넘길 때 열 크기가 필요한 이유를 설명해 줍니다.

Q5. C는 왜 배열 경계 검사를 하지 않나요? 그로 인한 문제와 대책은?

C는 "프로그래머를 믿고, 비용이 드는 일은 강제하지 않는다"는 철학으로 설계되었습니다. 배열 접근이 단순한 주소 계산과 메모리 접근으로 번역되어 매우 빠르지만, 범위를 벗어난 접근은 미정의 동작이며 다른 변수나 반환 주소를 덮어쓰는 버퍼 오버플로로 이어져 보안 취약점이 될 수 있습니다. 대책으로는 길이를 항상 함께 전달하고 검사하기, 크기 제한 함수 사용, 컴파일러 경고와 AddressSanitizer, 정적 분석 도구 적용, 스택 보호(canary) 같은 컴파일러·OS 방어 기법 활용이 있습니다.

Q6. 2차원 배열을 함수 매개변수로 받을 때 왜 열 크기를 생략할 수 없나요? int **로 받으면 안 되나요?

2차원 배열 int m[3][5]는 int[5]짜리 행 3개가 연속된 "배열의 배열"이고, m은 첫 행을 가리키는 int (*)[5]로 변환됩니다. m[i][j]의 주소를 계산하려면 한 행의 크기, 즉 열 개수를 알아야 하므로 생략할 수 없습니다. int **는 "포인터들의 배열"을 가리키는 형으로, 메모리 구조가 전혀 다르기 때문에 2차원 배열을 int **로 받으면 요소 값을 주소로 착각해 잘못된 메모리에 접근하게 됩니다.

Q7. 함수에서 배열을 반환할 수 있나요?

C에서 배열 자체를 반환형으로 쓸 수는 없습니다. 지역 배열의 이름을 반환하면 첫 요소의 주소가 반환되는데, 함수가 끝나면 지역 배열의 수명이 끝나 댕글링 포인터가 됩니다. 대안은 호출자가 배열을 준비해 포인터와 길이를 넘기는 방식, 동적 할당 후 포인터를 반환하고 호출자가 해제하는 방식, 배열을 구조체로 감싸 구조체를 값으로 반환하는 방식, 그리고 static 배열을 반환하는 방식(재진입·스레드 안전성 문제 있음)이 있습니다.

Q8. memcpy와 memmove의 차이는 무엇인가요?

둘 다 지정한 바이트 수만큼 메모리를 복사하지만, memcpy는 원본과 대상 영역이 겹치면 결과가 정의되지 않고, memmove는 겹치는 경우에도 올바르게 복사되도록 복사 방향을 조정하거나 임시 버퍼를 사용한 것처럼 동작합니다. 그래서 memcpy가 조금 더 빠를 수 있고, 같은 배열 안에서 요소를 밀거나 당길 때는 memmove를 써야 합니다.

연습문제 10-1 출력 예측 난이도 ★☆☆

정답과 해설 보기

p는 a + 1, 즉 a[1]을 가리키므로 *p = 4입니다. p[2] = *(p + 2) = *(a + 3) = a[3] = 8입니다. p가 배열 중간을 가리키면 "p 기준 인덱스"와 "a 기준 인덱스"가 달라지므로 p[k] == a[(p - a) + k]로 바꿔 생각하면 실수를 줄일 수 있습니다. *(a + 4) = a[4] = 10이고, *a + 4는 (*a) + 4 = 2 + 4 = 6입니다.

연습문제 10-7 배열 포인터 난이도 ★★★

int m[2][3] = {{1, 2, 3}, {4, 5, 6}};일 때 다음 값을 구하세요. m[0][0]의 주소는 100입니다. (1) m + 1 (2) *(m + 1) (3) *(*(m + 1) + 2) (4) sizeof m[0] (5) **m

정답과 해설 보기
  1. m은 int (*)[3]로 decay, 한 행 = 12바이트 → 112 (둘째 행 전체의 주소)
  2. *(m + 1)은 둘째 행 배열 m[1]이고, 식에서 다시 첫 요소 주소로 decay → 값 112 (자료형 int *)
  3. 112 + 2×4 = 120의 int → m[1][2] = 6
  4. m[0]은 int[3] 배열이므로 sizeof는 decay 예외 → 12
  5. *m = m[0] → decay → &m[0][0], 다시 * → m[0][0] = 1

연습문제 10-8 회전 이동 난이도 ★★★

배열을 왼쪽으로 k칸 회전하는 함수 void rotate_left(int *a, size_t n, size_t k)를 이 장에서 만든 reverse만 사용하여 작성하세요. {1,2,3,4,5,6,7}을 k=2로 회전하면 {3,4,5,6,7,1,2}입니다.

정답과 해설 보기

"세 번 뒤집기" 기법입니다. ① 앞 k개를 뒤집고 ② 나머지 n-k개를 뒤집고 ③ 전체를 뒤집으면 왼쪽 회전이 됩니다. 추가 배열 없이 O(n)에 끝납니다. reverse가 "포인터 + 길이"를 받으므로 a + k로 뒷부분만 넘길 수 있다는 점이 핵심입니다.

연습문제 10-9 금융 응용 — 일별 잔액 추이 난이도 ★★☆

시작 잔액과 거래 배열을 받아, 각 거래 직후의 잔액을 결과 배열에 채우는 함수 void running_balance(long long start, const long long *trx, long long *out, size_t n)를 작성하세요. 시작 1,000,000원, 거래 {-200000, 50000, -900000}일 때 out을 출력하고, 잔액이 음수가 되는 첫 거래의 번호(1부터)를 반환하도록 반환형을 int로 바꿔 보세요(없으면 0).

정답과 해설 보기

입력 배열(trx)은 const, 출력 배열(out)은 const 없이 받아 역할을 원형에서 구분합니다. out의 길이가 n 이상이라는 것은 호출자의 책임이므로 함수 주석에 명시해야 합니다.

연습문제 10-10 끝 표시 방식 난이도 ★★☆

거래 금액 배열의 끝을 -1로 표시하는 규약이 있습니다(금액은 항상 0 이상). 길이를 받지 않고 합계를 구하는 함수를 작성하고, 이 방식의 위험성 두 가지를 쓰세요.

정답과 해설 보기

위험성: ① 끝 표시 -1을 빠뜨리면 배열 끝을 넘어 계속 읽어 UB(쓰레기 값 누적 또는 segfault)가 됩니다. ② 정상 데이터로 -1이 나올 수 있게 규약이 바뀌면(예: 출금을 음수로 표현) 중간에서 멈춰 버립니다. 문자열의 '\0' 방식이 바로 이 구조라서, 12장에서 볼 버퍼 오버플로 문제의 뿌리가 됩니다.

연습문제 10-11 개념 서술 난이도 ★★☆

"배열을 함수에 넘길 때 길이를 함께 넘겨야 하는 이유"를 decay, 값에 의한 전달, sizeof라는 세 단어를 사용해 설명하세요.

정답과 해설 보기

모범 답안: 함수 호출 인자에 배열 이름을 쓰면 decay 규칙에 의해 첫 요소의 주소로 변환되고, C는 값에 의한 전달이므로 그 주소값만 매개변수에 복사됩니다. 매개변수는 배열이 아니라 포인터이므로 함수 안에서 sizeof를 하면 배열 크기가 아닌 포인터 크기가 나오고, 요소가 몇 개인지 알아낼 방법이 없습니다. 따라서 호출자가 배열이 선언된 범위에서 sizeof로 구한 길이를 별도 인자로 넘겨야 합니다.
