문자열

C에는 "문자열 자료형"이 없습니다. 문자열은 '\0'으로 끝나는 char 배열이고, 우리는 대부분 그 첫 글자의 주소(포인터)로 문자열을 다룹니다. 9~11장의 포인터·배열·문자 지식이 모두 여기서 만납니다. 동시에 문자열은 C 프로그램 보안 사고의 가장 큰 원인이기도 합니다. 계좌번호·고객명·전문을 다루는 금융 시스템에서 문자열 함수의 함정을 정확히 아는 것은 선택이 아니라 필수입니다.

이 장에서 배울 것

  • 문자열 상수가 읽기 전용 영역에 저장되는 이유와, 이를 수정하면 segfault가 나는 원리를 이해합니다.
  • char s[]와 char *s의 차이(저장 위치, sizeof, 수정 가능 여부)를 그림으로 구분합니다.
  • 2차원 char 배열과 포인터 배열로 문자열 여러 개를 다룹니다.
  • strlen, strcpy, strncpy, strcat, strcmp, strchr, strstr, strtok, snprintf, strtol의 정확한 동작과 함정을 압니다.
  • 주요 문자열 함수를 직접 구현하며 '\0' 종료 규약을 몸에 익힙니다.
  • 버퍼 오버플로의 원리와 안전한 대안을 알고, 계좌번호 하이픈 제거·마스킹 함수를 작성합니다.

12-1문자열과 포인터

8장에서 문자열을 "널 문자('\0')로 끝나는 char 배열"로 배웠습니다. 이 정의는 여전히 정확합니다. 이번 절에서는 여기에 포인터라는 렌즈를 더해, 문자열이 메모리의 어디에 저장되고 어떻게 전달되는지를 살펴봅니다.

문자열 상수는 어디에 저장되는가

큰따옴표로 쓴 "KRW"를 문자열 리터럴(string literal) 또는 문자열 상수라고 합니다. 컴파일러는 이것을 보면 다음 일을 합니다.

  1. 'K', 'R', 'W', '\0' 네 바이트짜리 이름 없는 char 배열(char [4])을 만듭니다.
  2. 이 배열을 실행 파일의 읽기 전용 데이터 영역(.rodata)에 넣습니다. 프로그램이 시작될 때 메모리에 올라와 종료될 때까지 존재합니다(정적 저장 기간).
  3. 코드에서 "KRW"를 식으로 쓴 자리는, 배열의 decay 규칙(10장)에 따라 그 배열의 첫 글자 주소로 바뀝니다.

printf("%s", cur)는 어떻게 문자열 끝을 알까?

%s에는 길이 정보가 전달되지 않습니다. printf가 받은 것은 주소 하나뿐입니다. printf는 그 주소에서 시작해 한 바이트씩 출력하다가 값이 0인 바이트('\0')를 만나면 멈춥니다. 그래서 C의 문자열은 반드시 '\0'으로 끝나야 하며, 이것을 "널 종료 문자열(null-terminated string)" 규약이라고 부릅니다. 10장에서 본 "끝 표시(sentinel)" 방식 그대로입니다. 그러므로 cur + 1을 넘기면 'R'부터 출력하고, '\0'이 없는 배열을 넘기면 메모리의 다음 0 바이트를 만날 때까지 쓰레기를 출력합니다.

char 배열과 char 포인터 — 무엇이 다른가

다음 두 줄은 비슷해 보이지만 완전히 다른 일을 합니다.

문자열 상수를 수정하면 왜 segfault가 날까

하드웨어가 막는다 — 페이지 보호 비트

C 표준은 "문자열 리터럴을 수정하려 하면 미정의 동작"이라고만 정합니다. 실제로 죽는 이유는 운영체제와 CPU에 있습니다.

  1. 링커는 문자열 리터럴을 .rodata 구역에 모으고, 운영체제는 프로그램을 실행할 때 이 구역이 담긴 메모리 페이지(보통 4KB 단위)를 "읽기 전용"으로 표시해 매핑합니다(페이지 테이블의 쓰기 허용 비트를 끔).
  2. code[0] = 'K'가 실행되면 CPU의 MMU가 해당 페이지에 쓰기 권한이 없음을 발견하고 보호 위반 예외(페이지 폴트)를 일으킵니다.
  3. 운영체제는 이를 정당한 접근이 아니라고 판단하고 프로세스에 SIGSEGV를 보내 종료시킵니다.

이렇게 설계한 이유는 두 가지입니다. ① 같은 리터럴을 여러 곳에서 공유(12-1-4)해도 안전하게 하려고, ② 여러 프로세스가 같은 실행 파일을 띄울 때 읽기 전용 페이지를 물리 메모리 한 벌로 공유해 메모리를 아끼려고. 오래된 컴파일러나 임베디드 환경에서는 리터럴이 쓰기 가능한 영역에 있어 죽지 않고 "조용히 바뀌는" 경우도 있는데, 그것이 더 위험합니다.

이렇게 해결합니다

  • 리터럴을 가리키는 포인터는 항상 const char *로 선언합니다. 그러면 code[0] = 'K'가 컴파일 오류로 바뀌어 실행 전에 잡힙니다.
  • 수정해야 하는 문자열은 배열로 복사본을 만듭니다: char code[] = "krw"; code[0] = 'K';
  • gcc의 -Wwrite-strings 옵션을 켜면 리터럴의 자료형을 const char[]처럼 취급해 char *code = "krw";에서 경고를 냅니다. (C++에서는 이 대입 자체가 오류입니다.)

왜 C의 리터럴 자료형은 const char[]가 아니라 char[]일까?

역사적 이유입니다. const는 C89에서야 도입되었는데, 그 전에 작성된 엄청난 양의 코드가 char *s = "...";를 쓰고 있었습니다. 리터럴을 const로 바꾸면 이 코드가 전부 컴파일 오류가 나므로, C 표준은 자료형은 char[N]으로 두되 "수정하면 UB"라는 규칙으로 타협했습니다. 그래서 C에서는 컴파일러가 막아 주지 않으니 프로그래머가 스스로 const를 붙여야 합니다.

같은 문자열 리터럴과 == 비교의 함정

두 문자열이 같은지 ==로 비교하면 어떻게 될까요? ==는 포인터, 즉 주소를 비교합니다. 내용이 아닙니다.

a == b가 "같다"인 것은 우연이다

gcc는 같은 내용의 리터럴을 .rodata에 한 벌만 두고 공유하는 문자열 풀링(string pooling) 최적화를 합니다. 그래서 a와 b가 같은 주소를 갖게 되었을 뿐, 표준은 이를 보장하지 않습니다. 다른 파일에 있는 같은 리터럴이나 다른 컴파일러에서는 "다르다"가 나올 수 있습니다. 이런 코드는 테스트에서 통과하다가 빌드 옵션이 바뀌면 깨집니다. 문자열 내용 비교는 반드시 strcmp로 합니다.

문자열 배열 — 2차원 char 배열과 포인터 배열

통화 코드 목록처럼 문자열 여러 개를 다루는 방법은 두 가지입니다.

무엇을 언제 쓸까?

둘 다 sizeof가 24로 같은 것은 우연입니다(3×8 바이트 배열 vs 포인터 3개×8바이트). 의미는 전혀 다릅니다.

  • 2차원 char 배열: 내용을 수정해야 하거나(입력받은 이름 저장), 고정 길이 레코드처럼 각 칸의 크기가 정해진 경우에 씁니다. 가장 긴 문자열에 맞춰 칸을 잡으므로 짧은 문자열이 많으면 공간이 낭비됩니다.
  • 포인터 배열: 길이가 제각각인 고정 문구 테이블(메뉴, 오류 메시지, 거래 코드명)에 적합합니다. 공간 낭비가 없고, 포인터만 바꾸면 되므로 정렬할 때 문자열을 복사하지 않고 포인터만 교환하면 되어 빠릅니다. 리터럴을 가리킨다면 반드시 const char *로 선언합니다.

한글 "원화"가 7바이트인 이유는 UTF-8에서 한글 한 글자가 3바이트이고 '\0'이 1바이트이기 때문입니다(3+3+1). "미국 달러"는 한글 4글자(12) + 공백(1) + '\0'(1) = 14바이트입니다.

은행 시스템에서는 — 응답 코드 메시지 테이블

계정계는 처리 결과를 "0000", "E102" 같은 응답 코드로 돌려주고, 채널(인터넷뱅킹·ATM·창구 단말)은 이를 고객용 메시지로 바꿔 보여 줍니다. 이 매핑은 흔히 static const struct { const char *code; const char *msg; } RESP_TBL[] = { {"0000", "정상 처리되었습니다"}, {"E102", "잔액이 부족합니다"}, ... };처럼 포인터 배열(구조체 배열)로 만들어 읽기 전용 영역에 둡니다. const로 선언하면 실수로 메시지를 바꾸는 코드가 컴파일 단계에서 막히고, 여러 프로세스가 같은 실행 파일을 띄울 때 이 테이블이 물리 메모리 한 벌로 공유됩니다. 반대로 고객명처럼 입력받아 가공하는 문자열은 고정 크기 char name[41] 같은 배열에 담아 수정 가능하게 둡니다. 실무 코딩 표준에서 필드 길이를 "실제 길이 + 1('\0')"로 잡는 것이 바로 이 장의 널 종료 규약 때문입니다.

다음 각 줄이 (A) 정상, (B) 컴파일 오류, (C) 컴파일되지만 UB 중 무엇인지 고르세요.

(1) A — 배열 복사본 수정. (2) C — 리터럴 수정, 보통 segfault. (3) B — const를 통한 수정은 컴파일 오류. 이것이 const를 붙이는 이유입니다. (4) B — 배열 이름에는 대입 불가. 내용을 바꾸려면 strcpy 등을 써야 합니다. (5) A — 포인터가 다른 리터럴을 가리킴. (6) A — char *를 const char *에 넣는 것은 보호를 더하는 방향이므로 자유롭습니다.

12-2문자열 연산 함수

C에는 문자열 자료형이 없으므로 s1 = s2(복사), s1 + s2(연결), s1 == s2(비교) 같은 연산자를 쓸 수 없습니다. 대신 <string.h>의 함수를 사용합니다. 이 함수들은 모두 "주소를 받아 '\0'을 만날 때까지 처리한다"는 같은 원리로 동작하며, 대부분 대상 버퍼의 크기를 확인하지 않습니다. 이 한 가지 사실이 수십 년간 수많은 보안 사고의 원인이 되었습니다. 함수마다 동작과 함정을 정확히 짚어 봅시다.

strlen — 길이 구하기

strlen은 실행 중에, sizeof는 컴파일할 때

sizeof는 컴파일러가 자료형만 보고 계산하는 컴파일 시점 연산자입니다. 배열에 무엇이 들어 있는지는 상관없이 "확보된 공간"을 알려 줍니다. strlen은 실행 시점 함수로, 주소부터 한 바이트씩 세면서 '\0'을 찾습니다. 그래서 길이 n의 문자열에 O(n) 시간이 걸립니다.

이 사실은 성능 함정을 만듭니다. for (i = 0; i < strlen(s); i++)는 반복할 때마다 strlen을 다시 호출하므로 전체가 O(n²)이 됩니다. 10만 바이트 전문이라면 약 100억 번의 비교입니다. 루프 전에 size_t len = strlen(s);로 한 번만 구해 두세요. (최적화 컴파일러가 대신 해 주기도 하지만, 루프 안에서 s를 수정하면 그럴 수 없습니다.)

strcpy와 strncpy — 복사와 그 함정

배열 이름에는 대입할 수 없으므로 문자열 복사는 strcpy(대상, 원본)으로 합니다. 원본의 '\0'까지 포함해 복사합니다. 문제는 대상의 크기를 전혀 모른다는 점입니다.

그래서 "크기를 지정하는" strncpy가 안전한 대안처럼 소개되곤 합니다. 하지만 strncpy는 원래 고정 길이 필드(옛 유닉스의 14바이트 파일 이름 항목)를 채우기 위해 만든 함수라서, 일반 문자열 복사용으로 쓰면 함정이 있습니다.

strncpy의 두 가지 문제

  1. 널 종료 미보장: 원본 길이가 n 이상이면 정확히 n바이트만 복사하고 '\0'을 붙이지 않습니다. 이후 이 배열을 문자열로 쓰는 모든 함수(printf, strlen, strcpy)가 배열 밖까지 읽어 UB가 됩니다.
  2. 불필요한 0 채우기: 원본이 짧으면 n바이트가 될 때까지 나머지를 전부 '\0'으로 채웁니다. 4KB 버퍼에 3글자를 복사해도 4KB를 씁니다. 대량 처리에서 성능 낭비입니다.

그래서 strncpy를 쓸 때는 반드시 strncpy(d, s, sizeof d - 1); d[sizeof d - 1] = '\0'; 두 줄을 세트로 씁니다. 더 간단하고 안전한 방법은 snprintf(d, sizeof d, "%s", s);입니다(12-2-7). BSD 계열의 strlcpy, C11 부록 K의 strcpy_s도 있지만 glibc에는 오랫동안 없었고 부록 K는 지원 구현이 적어 이식성이 떨어집니다.

그래도 strncpy가 딱 맞는 곳 — 고정 길이 전문 필드

strncpy의 "0으로 채우기, 널 종료 없음" 동작은 사실 고정 길이 필드를 위한 것입니다. 전문의 10바이트 필드는 '\0' 없이 정확히 10바이트여야 하므로 strncpy가 의도에 맞습니다. 다만 금융 전문은 보통 '\0'이 아니라 공백으로 채우는 규칙이 많아서, 실무에서는 memset(field, ' ', 10); memcpy(field, src, len < 10 ? len : 10); 같은 전용 함수를 따로 만들어 씁니다.

strcat과 strncat — 이어 붙이기

strcat의 숨은 비용과 strncat 계산식

strcat은 붙이기 전에 대상의 '\0'을 찾기 위해 처음부터 끝까지 훑습니다. 그래서 반복문 안에서 strcat을 계속 호출해 긴 문자열을 만들면 매번 처음부터 다시 세므로 O(n²)이 됩니다(일명 "화가 슐레미엘의 알고리즘"). 많이 이어 붙일 때는 현재 끝 위치를 포인터로 기억해 두고 그 자리에 복사하는 편이 낫습니다.

strncat의 세 번째 인자는 버퍼 크기가 아니라 "덧붙일 최대 글자 수"입니다. small은 12바이트, 현재 "ID:"가 3글자이므로 남은 자리는 12 − 3 − 1('\0' 몫) = 8글자입니다. 그래서 "CUST-000"까지 8글자만 붙고 '\0'이 추가되어 총 11글자가 됩니다. strncat(small, src, sizeof small)처럼 버퍼 크기를 그대로 넘기는 것은 매우 흔한 실수로, 오버플로를 막지 못합니다.

strcmp — 문자열 비교

strcmp(a, b)는 두 문자열을 앞에서부터 한 글자씩 비교하다가 처음으로 다른 글자를 만나면 그 차이에 따라 결과를 냅니다.

  • a가 사전 순으로 앞서면 음수, 같으면 0, 뒤면 양수.
  • 비교는 각 글자를 unsigned char로 본 값으로 합니다. 그래서 대문자가 소문자보다 앞서고, 한 문자열이 다른 문자열의 앞부분이면 짧은 쪽이 앞섭니다('\0'(0)이 가장 작으므로).

자주 하는 실수 3가지

  • if (strcmp(a, b) == 1): strcmp는 −1/1이 아니라 "음수/양수"를 반환합니다. glibc는 글자 차이(예: 'U'−'E' = 16)를 반환하기도 하므로 > 0, < 0으로 검사해야 합니다.
  • if (strcmp(a, b))를 "같으면 참"으로 착각: 같을 때 0(거짓)입니다. 의도를 분명히 하려면 strcmp(a, b) == 0으로 씁니다.
  • if (a == b): 주소 비교입니다(12-1-4).

직접 구현해 보기 — strlen, strcpy, strcmp

표준 함수를 직접 구현해 보면 '\0' 규약과 포인터 연산이 손에 익고, 함정이 왜 생기는지 저절로 이해됩니다. 면접에서도 자주 나오는 문제입니다.

while ((*dst++ = *src++) != '\0') 한 줄 해부

  1. *src++: src가 가리키는 글자를 읽고, src를 다음 칸으로 옮깁니다(후위 증가는 증가 전 주소를 사용).
  2. *dst++ = ...: 그 글자를 dst가 가리키는 칸에 쓰고, dst를 다음 칸으로 옮깁니다.
  3. 대입식의 값은 대입된 글자이므로, 그것이 '\0'이면 반복을 끝냅니다. '\0'까지 복사된 뒤에 멈추므로 결과는 항상 널 종료됩니다.

이 코드에는 dst의 크기를 검사하는 부분이 전혀 없습니다. 함수는 dst가 충분히 크다고 믿을 수밖에 없습니다. 받은 것이 주소뿐이니까요(10장의 "배열을 넘기면 길이가 사라진다"). 이것이 strcpy가 위험한 근본 이유이며, 안전한 함수들은 모두 크기를 추가 인자로 받습니다.

my_strcmp에서 (unsigned char)로 바꾸는 이유는, 한글 UTF-8 바이트(0x80 이상)가 signed char에서 음수가 되어 "가" < "A"처럼 순서가 뒤집히는 것을 막기 위해서입니다. 표준 strcmp도 unsigned char 기준으로 비교하도록 규정되어 있습니다.

예제 12-2 난이도 ★★☆

버퍼 크기를 받아 항상 널 종료를 보장하고, 잘렸는지 알려 주는 안전한 복사 함수 int safe_copy(char *dst, size_t size, const char *src)를 작성하세요. 전부 복사되면 0, 잘렸으면 1, size가 0이면 -1을 반환합니다.

정답과 해설 보기

핵심은 ① 최대 size − 1글자만 복사하고 ② 마지막에 반드시 '\0'을 쓰며 ③ 잘림 여부를 호출자에게 알리는 것입니다. 금융 데이터에서 "조용히 잘리는 것"은 오류보다 위험할 수 있습니다. 계좌번호 끝자리가 잘려 다른 계좌가 되는 상황을 생각해 보세요. 그래서 잘림을 오류로 처리할지 호출자가 결정할 수 있도록 반환값으로 알려 줍니다.

strchr, strrchr, strstr — 찾기

찾기 함수는 찾은 위치를 포인터로 돌려줍니다. 못 찾으면 NULL입니다. 찾은 포인터에서 시작 주소를 빼면 인덱스가 됩니다(10장의 포인터 뺄셈).

'급여'의 위치가 5인 이유와 NULL 검사

"3월 급여"에서 '3'은 1바이트, '월'은 UTF-8로 3바이트, 공백 1바이트이므로 '급'은 0 + 1 + 3 + 1 = 5번째 바이트에서 시작합니다. 문자열 함수는 모두 바이트 단위로 동작한다는 점을 기억하세요. strstr은 바이트열을 그대로 비교하므로 UTF-8 한글 검색도 정확하게 동작하지만, 결과 위치는 글자 수가 아니라 바이트 수입니다.

못 찾았을 때의 NULL을 검사하지 않고 printf("%s", p)나 p - acct를 쓰면 9장의 널 포인터 역참조가 됩니다. glibc의 printf는 NULL에 대해 "(null)"을 찍어 주기도 하지만 이는 비표준 친절일 뿐이며, 다른 환경에서는 바로 죽습니다.

strtok — 구분자로 나누기

CSV 형식의 거래 기록 "20261028,110-234-567890,WD,50000"을 쉼표로 나누려면 strtok을 씁니다. 첫 호출에는 문자열을, 이후 호출에는 NULL을 넘기면 "이어서" 다음 토큰을 돌려줍니다.

strtok의 함정 4가지

  1. 원본을 수정합니다. 그래서 문자열 리터럴(char *line = "a,b";)을 넘기면 읽기 전용 메모리에 쓰려다 segfault가 납니다. 원본을 보존해야 하면 복사본에 사용합니다.
  2. 내부에 정적 변수로 "다음 위치"를 기억합니다. 그래서 strtok으로 줄을 나누는 도중에 다른 함수가 strtok을 호출하면 위치가 덮어써집니다. 멀티스레드 환경에서도 안전하지 않습니다(재진입 불가). POSIX의 strtok_r(s, delim, &saveptr)은 상태를 호출자의 변수에 저장해 이 문제를 해결합니다(윈도우는 strtok_s).
  3. 연속된 구분자를 하나로 취급하고 빈 필드를 건너뜁니다. "20261028,,WD"는 토큰 2개("20261028", "WD")가 되어, 비어 있는 계좌번호 필드가 사라지고 필드 순서가 밀립니다. CSV처럼 빈 필드가 의미 있는 형식에는 부적합하므로 strchr로 직접 나누거나 POSIX strsep을 씁니다.
  4. 토큰 포인터는 원본 배열 안을 가리키므로, 원본 배열의 수명이 끝나면 함께 무효가 됩니다.

snprintf — 안전하게 문자열 만들기

sprintf는 printf의 출력을 화면 대신 문자열 버퍼에 쓰는 함수입니다. 역시 버퍼 크기를 모르므로 위험합니다. C99의 snprintf(buf, size, fmt, ...)는 최대 size − 1글자만 쓰고 항상 '\0'을 붙이며, 반환값으로 "잘리지 않았다면 썼을 글자 수"를 알려 줍니다.

반환값이 "쓴 길이"가 아니라 "필요한 길이"인 이유

"TRX20261028-000042"는 18글자입니다. 버퍼가 16바이트이므로 15글자 + '\0'만 들어갔지만, 반환값은 18입니다. 이렇게 설계한 덕분에 ① n >= size이면 잘렸다는 것을 알 수 있고, ② n + 1바이트를 할당해 다시 호출하면 정확히 맞는 버퍼를 만들 수 있습니다. 거래 키나 파일 이름처럼 잘리면 안 되는 문자열은 반드시 반환값을 검사해야 합니다. 잘린 거래 키 두 개가 우연히 같아져 중복 키 오류가 나는 장애는 실제로 일어나는 유형입니다.

strtol과 atoi — 문자열을 숫자로

11장에서 숫자 문자열을 직접 변환해 보았습니다. 표준 라이브러리에는 atoi, atol과 strtol, strtoll이 있습니다. 둘의 결정적 차이는 오류를 알 수 있는가입니다.

입력atoi 결과strtoll로 알 수 있는 것
"15000"15000값 15000, end가 문자열 끝 → 정상
"15000abc"15000 (뒤를 조용히 무시)end가 "abc"를 가리킴 → 형식 오류 판단 가능
"abc"0 (정상 0과 구분 불가)end == 시작 → 숫자 없음
"99999999999999999999"미정의 동작LLONG_MAX 반환, errno == ERANGE

왜 금융 시스템에서 atoi는 금지인가

atoi는 실패를 알릴 방법이 없습니다. "abc"도 0, "0"도 0입니다. 사용자가 이체 금액에 "5O000"(숫자 0 대신 영문 O)을 입력하면 atoi는 5를 돌려주고, 프로그램은 5원 이체를 정상 처리합니다. 범위를 넘는 입력은 아예 미정의 동작입니다. strtoll은 ① 변환이 멈춘 위치(end)로 형식 오류를, ② errno로 범위 초과를 알려 주므로 입력을 엄격하게 검증할 수 있습니다. 앞쪽 공백은 strtoll이 알아서 건너뛰고, '+'·'-' 부호도 처리합니다. 금액이라면 추가로 음수와 0을 업무 규칙에 따라 거부해야 합니다. 많은 금융권 시큐어 코딩 지침이 atoi 계열 대신 strtol 계열 사용을 권고하는 이유입니다.

버퍼 오버플로와 안전한 대안

지금까지 여러 번 "버퍼 오버플로"를 언급했습니다. 정확히 어떤 일이 일어나는지 스택 그림으로 확인해 봅시다.

왜 이렇게 위험할까?

함수의 지역 변수와 "함수가 끝나면 돌아갈 주소(반환 주소)"는 같은 스택에 나란히 저장됩니다. strcpy는 '\0'을 만날 때까지 낮은 주소에서 높은 주소 방향으로 쓰기 때문에, 입력이 pin보다 길면 그 위의 데이터를 차례로 덮어씁니다. 이웃 변수 ok가 0이 아닌 값으로 바뀌면 PIN이 틀려도 "인증 성공"이 나오고, 반환 주소가 공격자가 고른 값으로 바뀌면 함수가 return 하는 순간 CPU가 그 주소로 점프합니다. 1988년 모리스 웜 이래 수많은 해킹이 이 원리를 이용했습니다.

현대 시스템에는 스택 카나리(-fstack-protector: 반환 주소 앞에 비밀 값을 두고 return 전에 변조 여부 검사), NX 비트(스택에서 코드 실행 금지), ASLR(주소 무작위화) 같은 방어 기법이 있어 공격이 훨씬 어려워졌습니다. 하지만 이는 피해를 줄이는 장치일 뿐, 이웃 변수 변조 같은 논리 오류는 막지 못합니다. 근본 대책은 버퍼 크기를 넘는 쓰기를 처음부터 하지 않는 것입니다.

위험한 함수안전한 대안비고

fgets의 동작과 '\n' 제거 관용구

fgets(buf, n, fp)는 최대 n − 1바이트까지, 또는 '\n'을 읽을 때까지(그 '\n'도 저장) 읽고 항상 '\0'을 붙입니다. 그래서 버퍼를 넘치지 않습니다. 대신 ① 저장된 '\n'을 직접 지워야 하고, ② 입력이 n − 1자보다 길면 나머지가 입력 버퍼에 남아 다음 fgets가 그것을 읽습니다(11장의 버퍼 문제와 같은 원리).

name[strcspn(name, "\n")] = '\0';은 '\n'의 위치(없으면 문자열 끝, 즉 strlen)를 구해 그 자리에 '\0'을 쓰는 관용구입니다. '\n'이 없을 때도 안전하게 동작합니다. 반대로 name[strlen(name) - 1] = '\0';은 '\n'이 없는 경우 마지막 글자를 지우고, 빈 문자열이면 name[-1](실제로는 size_t 언더플로로 거대한 인덱스)에 써 버리는 버그가 있습니다. '\n'이 없다는 것은 줄이 버퍼보다 길었다는 뜻이므로, 엄격한 프로그램이라면 그 경우 남은 입력을 버리고 "입력이 너무 깁니다" 오류를 냅니다.

금융 예제 — 계좌번호 하이픈 제거와 마스킹

은행 시스템에서 계좌번호는 화면에는 "123-4567-7890"처럼 하이픈을 넣어 보여 주고, 원장 조회 키로는 "12345677890"처럼 숫자만 쓰며, 로그·영수증·알림 문자에는 "123-****-7890"처럼 가운데를 가려서(마스킹) 남깁니다. 이 장에서 배운 포인터·배열·문자 판별·널 종료 규약을 모두 사용해 이 기능을 만들어 봅시다.

  1. remove_hyphen: 숫자만 골라 복사합니다. 숫자·하이픈 외의 문자가 있으면 오류, 대상 버퍼가 작으면 오류입니다.
  2. mask_account: 하이픈 위치는 그대로 두고, 숫자 중 앞 3자리와 뒤 4자리만 남기고 나머지를 '*'로 바꿉니다. 계좌번호 체계마다 하이픈 위치가 달라도 동작하도록 "숫자 순번" 기준으로 판단합니다.
  3. 두 함수 모두 대상 버퍼 크기를 받아 오버플로를 막고, 항상 널 종료합니다. 원본은 const로 보호합니다.

설계 포인트 다시 보기

  • 하이픈 위치가 아니라 숫자 순번으로 판단: 은행마다, 상품마다 계좌번호 자릿수와 하이픈 위치가 다릅니다(3-3-6, 3-4-4, 6-2-6 등). "첫 하이픈과 마지막 하이픈 사이를 가린다"는 규칙은 하이픈 없는 입력에서 아무것도 가리지 못하는 사고로 이어집니다. 숫자 순번 기준이면 형식과 무관하게 같은 개수의 숫자가 노출됩니다.
  • 두 번 순회: 뒤에서 4자리를 판단하려면 전체 숫자 개수를 먼저 알아야 하므로 1차로 세고 2차로 마스킹합니다.
  • 버퍼 크기 검사: remove_hyphen은 쓰기 직전마다 n + 1 >= size를 검사해 '\0' 자리까지 확보합니다. mask_account는 결과 길이가 원본과 같으므로 시작할 때 한 번만 검사합니다.
  • 실패 시 dst를 빈 문자열로: 오류가 나도 dst가 쓰레기나 반쯤 만들어진 값으로 남지 않게 합니다. 호출자가 실수로 dst를 출력해도 안전합니다.
  • 가릴 것이 없으면 거부: 숫자가 7개 이하인데 "마스킹 성공"으로 원본을 그대로 돌려주면 개인정보가 노출됩니다. 보안 기능은 애매할 때 실패하는 쪽이 안전합니다(fail-safe).

은행 시스템에서는 — 개인정보·금융정보 마스킹 의무

계좌번호, 카드번호, 주민등록번호 같은 정보는 관련 법령과 금융권 보안 가이드에 따라 화면 출력·로그·출력물에서 일부를 가려야 합니다. 예를 들어 카드번호는 흔히 "1234-56**-****-7890"처럼 앞 6자리와 뒤 4자리만 남기는 방식이 쓰이고(PCI DSS 기준), 계좌번호·전화번호는 기관별 표준 규칙을 따릅니다. 실무에서 마스킹 함수는 ① 공통 모듈 하나로 만들어 전 시스템이 같은 규칙을 쓰게 하고, ② 로그 출력 함수 내부에서 자동 적용하며, ③ 원본 버퍼는 사용 후 memset으로 지워 메모리 덤프에 남지 않게 합니다. 특히 "디버깅용으로 전문 전체를 로그에 찍는" 코드가 운영에 반영되어 계좌번호가 평문으로 남는 사고가 감사에서 자주 지적되므로, 코드 리뷰와 정적 분석에서 중점적으로 확인합니다.

예제 12-3 난이도 ★★☆

숫자만으로 된 계좌번호 "110234567890"을 받아 "3-3-나머지" 형식의 하이픈을 넣는 함수 int format_account(const char *digits, char *dst, size_t size)를 작성하세요. 결과는 "110-234-567890"입니다.

정답과 해설 보기

원본 길이 n에 하이픈 2개가 더해지므로 결과 길이는 n + 2, 버퍼는 n + 3바이트 이상 필요합니다. 인덱스 3과 6 앞에 하이픈을 넣으며 복사합니다.

핵심 정리

  • C의 문자열은 '\0'으로 끝나는 char 배열이며, 함수에는 첫 글자의 주소로 전달됩니다. 문자열 함수는 '\0'을 만날 때까지 처리하므로 널 종료가 깨지면 UB입니다.
  • 문자열 리터럴은 정적 저장 기간을 가진 이름 없는 char 배열로, 보통 읽기 전용 영역(.rodata)에 저장됩니다. 수정하면 UB이며 실제로는 페이지 보호 위반으로 segfault가 납니다. 리터럴을 가리키는 포인터는 const char *로 선언합니다.
  • char s[] = "..."는 수정 가능한 복사본(sizeof = 길이 + 1), const char *s = "..."는 리터럴을 가리키는 포인터(sizeof = 8)입니다. 배열에는 대입이 불가하고, 포인터는 다른 문자열을 가리킬 수 있습니다.
  • 문자열 내용 비교는 strcmp(a, b) == 0으로 합니다. ==는 주소 비교이며, 리터럴 풀링 때문에 우연히 같게 나올 수 있습니다.
  • 2차원 char 배열은 고정 칸·수정 가능, 포인터 배열은 가변 길이·리터럴 테이블에 적합합니다.
  • strlen은 실행 시간 O(n), sizeof는 컴파일 시간 크기입니다. 루프 조건에 strlen을 반복 호출하지 않습니다.
  • strcpy·strcat·sprintf·gets는 대상 크기를 검사하지 않습니다. strncpy는 널 종료를 보장하지 않고, strncat의 n은 덧붙일 글자 수입니다. snprintf는 항상 널 종료하고 필요한 길이를 반환하므로 잘림을 검출할 수 있습니다.
  • strchr·strrchr·strstr은 못 찾으면 NULL을 반환합니다. strtok은 원본을 수정하고 정적 상태를 가지며 빈 필드를 건너뜁니다(strtok_r, strsep 대안).
  • atoi는 오류를 알릴 수 없고 범위 초과 시 UB입니다. strtol/strtoll로 end 포인터와 errno를 검사해 형식·범위 오류를 잡습니다.
  • 버퍼 오버플로는 이웃 변수와 반환 주소를 덮어써 보안 취약점이 됩니다. fgets + strcspn, snprintf, 폭 지정 scanf, 길이 검사로 예방합니다.
  • 계좌번호 마스킹은 숫자 순번 기준으로, 버퍼 크기를 검사하고, 실패 시 안전한 쪽(fail-safe)으로 동작하게 작성합니다.

CS 면접 단골 질문

이 장에서 나오는 면접 질문

Q1. char str[] = "abc"와 char *str = "abc"의 차이는?

첫 번째는 4바이트 배열을 만들고 리터럴의 내용을 복사하므로 지역 변수라면 스택에 수정 가능한 복사본이 생기고, sizeof는 4입니다. 두 번째는 읽기 전용 영역에 있는 리터럴의 주소를 포인터 변수에 저장하므로 sizeof는 포인터 크기 8이고, 글자를 수정하면 미정의 동작으로 보통 segfault가 납니다. 또 배열 이름에는 다른 문자열을 대입할 수 없지만 포인터는 다른 문자열을 가리키게 바꿀 수 있습니다.

꼬리 질문: "왜 segfault가 나나요?" → 리터럴이 .rodata에 있고, OS가 그 페이지를 읽기 전용으로 매핑해 MMU가 쓰기를 차단하기 때문이라고 답합니다.

Q2. 프로세스의 메모리 구조(코드, 데이터, BSS, 힙, 스택)를 설명하고, 문자열 리터럴·전역 변수·지역 변수·malloc 메모리는 각각 어디에 있나요?

낮은 주소부터 실행 코드가 있는 텍스트 영역, 읽기 전용 상수(.rodata), 초기화된 전역·정적 변수의 데이터 영역, 0으로 초기화되는 전역·정적 변수의 BSS, 위로 자라는 힙, 높은 주소에서 아래로 자라는 스택이 있습니다. 문자열 리터럴은 .rodata, 초기값이 있는 전역 변수는 데이터, 초기값이 없는 전역 변수는 BSS, 지역 변수는 스택, malloc으로 받은 메모리는 힙에 있습니다.

Q3. strcpy와 strncpy의 차이와 각각의 문제점은?

strcpy는 원본의 '\0'까지 복사하지만 대상 버퍼의 크기를 검사하지 않아 버퍼 오버플로가 생길 수 있습니다. strncpy는 최대 n바이트만 복사하지만, 원본이 n바이트 이상이면 '\0'을 붙이지 않아 널 종료되지 않은 문자열을 만들고, 원본이 짧으면 남은 공간을 모두 0으로 채워 비효율적입니다. 그래서 strncpy 후 마지막 바이트에 직접 '\0'을 넣거나, snprintf나 길이 검사 후 memcpy를 쓰는 방식을 권장합니다.

Q4. 버퍼 오버플로란 무엇이고, 어떻게 방어하나요?

할당된 버퍼 크기를 넘어 데이터를 써서 인접 메모리를 덮어쓰는 현상입니다. 스택에서는 이웃 지역 변수나 반환 주소를 변조해 프로그램 흐름을 탈취할 수 있습니다. 방어는 코드 수준에서 크기를 받는 안전한 함수 사용과 입력 길이 검증, 컴파일러 수준에서 스택 카나리, OS 수준에서 ASLR과 NX(DEP) 같은 기법이 있습니다. 정적 분석과 AddressSanitizer로 사전에 찾아내는 것도 중요합니다.

Q5. strlen의 시간 복잡도는? sizeof와의 차이는?

strlen은 '\0'을 만날 때까지 한 바이트씩 세므로 O(n)이고 실행 시간에 계산됩니다. sizeof는 컴파일 시간에 자료형의 크기를 계산하는 연산자로, 배열이면 배열 전체 크기('\0'과 남은 공간 포함), 포인터면 포인터 크기를 돌려줍니다. 그래서 루프 조건에 strlen을 두면 O(n²)이 될 수 있어 미리 길이를 구해 두는 것이 좋습니다.

Q6. strcmp의 반환값과 두 문자열을 ==로 비교하면 안 되는 이유는?

strcmp는 첫 번째로 다른 문자를 unsigned char로 비교해 첫 문자열이 사전 순으로 앞서면 음수, 같으면 0, 뒤면 양수를 반환합니다. -1과 1로 정해진 것이 아니므로 부호로 판단해야 합니다. ==는 두 포인터의 주소를 비교하므로 내용이 같아도 다른 메모리에 있으면 거짓이고, 컴파일러의 리터럴 풀링 때문에 우연히 참이 될 수도 있어 신뢰할 수 없습니다.

Q7. atoi와 strtol의 차이는?

atoi는 변환 실패를 알릴 방법이 없어 "abc"와 "0"이 모두 0이 되고, 범위를 넘는 값은 미정의 동작입니다. strtol은 변환이 멈춘 위치를 end 포인터로 돌려주어 숫자가 없거나 뒤에 잘못된 문자가 있는지 확인할 수 있고, 범위를 넘으면 LONG_MAX나 LONG_MIN을 반환하며 errno를 ERANGE로 설정합니다. 진법도 지정할 수 있습니다. 그래서 입력 검증이 중요한 시스템에서는 strtol 계열을 씁니다.

Q8. strtok이 스레드 안전하지 않은 이유와 대안은?

strtok은 다음 토큰의 시작 위치를 함수 내부의 정적 변수에 저장해 두고, NULL을 넘긴 다음 호출에서 그 위치부터 이어서 처리합니다. 여러 스레드나 중첩된 호출이 같은 정적 변수를 공유하므로 서로의 위치를 덮어써 결과가 꼬입니다. 또 원본 문자열을 수정합니다. 대안으로 상태를 호출자 변수에 저장하는 POSIX strtok_r이나 윈도우의 strtok_s, 빈 필드를 보존하는 strsep을 쓰거나 strchr로 직접 파싱합니다.

Q9. gets 함수는 왜 표준에서 삭제되었나요?

gets는 버퍼 크기를 인자로 받지 않아 입력이 버퍼보다 길면 무조건 오버플로가 발생하고, 프로그래머가 이를 막을 방법이 원천적으로 없습니다. 실제 모리스 웜이 gets 취약점을 이용했을 정도로 위험해 C99에서 사용 중단 권고, C11에서 표준에서 완전히 삭제되었습니다. 대신 크기를 받는 fgets를 사용하고, 저장되는 개행 문자를 처리해야 합니다.

Q10. 문자열을 뒤집는 함수를 구현해 보세요. (화이트보드 단골)

strlen으로 길이를 구한 뒤 양 끝을 가리키는 두 포인터를 두고, 왼쪽이 오른쪽보다 작은 동안 두 글자를 교환하며 가운데로 이동합니다. 추가 메모리 없이 O(n)입니다. 길이가 0이면 끝 포인터 계산이 범위를 벗어나므로 먼저 처리해야 하고, 리터럴을 넘기면 수정할 수 없으므로 배열을 넘겨야 한다는 점, UTF-8 한글은 바이트 단위로 뒤집으면 깨진다는 점까지 언급하면 좋습니다.

연습문제 12-1 sizeof와 strlen 난이도 ★☆☆

64비트 리눅스에서 출력값을 쓰세요.

정답과 해설 보기

a는 크기를 10으로 지정했으므로 10, b는 초기값에 맞춰 3 + 1 = 4, c는 포인터 8입니다. strlen은 모두 '\0' 전까지인 3입니다.

연습문제 12-2 출력 예측 난이도 ★☆☆

정답과 해설 보기

s + 3은 'O'부터 → "OSIT". *(s + 1)은 'E'. strlen(s) = 7이므로 s + 4는 'S'부터 → "SIT". s[7]은 '\0'이므로 Y.

연습문제 12-3 버그 찾기 난이도 ★★☆

다음 코드의 문제를 모두 찾고 고치세요.

정답과 해설 보기
  1. code[0] = 'W': 리터럴 수정 → UB(segfault). char code[] = "wd";로 배열을 만들어야 합니다.
  2. strcpy(name, "WITHDRAW"): 9바이트를 4바이트 배열에 → 오버플로. 버퍼를 9 이상으로 키우거나 snprintf를 씁니다.
  3. code == "WD": 주소 비교. strcmp(code, "WD") == 0으로 고칩니다.

연습문제 12-4 strncpy 결과 난이도 ★★☆

char d[6] = "XXXXX"; strncpy(d, "AB", 4); 실행 후 d의 여섯 바이트를 쓰세요. 또 strncpy(d, "ABCDEFG", 6); 실행 후 printf("%s", d)가 위험한 이유를 쓰세요.

정답과 해설 보기

첫 번째: 'A' 'B' '\0' '\0' 'X' '\0'. 원본이 짧으므로 n = 4까지 '\0'으로 채우고, 5번째('X')와 6번째(원래의 '\0')는 그대로입니다. 두 번째: "ABCDEF" 6바이트만 복사되고 '\0'이 없으므로 printf가 d 뒤의 메모리까지 읽어 UB입니다.

연습문제 12-5 직접 구현 — strcat 난이도 ★★☆

버퍼 크기를 받아 안전하게 이어 붙이는 int safe_cat(char *dst, size_t size, const char *src)를 작성하세요. 전부 붙었으면 0, 잘렸으면 1, dst가 이미 널 종료되지 않았으면(size 안에 '\0' 없음) -1을 반환합니다.

정답과 해설 보기

strlen(dst)를 그냥 쓰지 않고 size 범위 안에서만 '\0'을 찾는 것이 핵심입니다. dst가 이미 널 종료되지 않았다면 strlen 자체가 버퍼 밖을 읽기 때문입니다(BSD strlcat과 같은 발상).

연습문제 12-6 문자열 뒤집기 난이도 ★★☆

ASCII 문자열을 제자리에서 뒤집는 void str_reverse(char *s)를 두 포인터로 작성하세요. "ABC123" → "321CBA".

정답과 해설 보기

10장의 배열 뒤집기와 같지만 길이를 strlen으로 구하고, '\0'은 제자리에 둡니다. 리터럴을 넘기면 안 되고(char s[] = "ABC123";로 호출), UTF-8 한글은 바이트 단위로 뒤집으면 깨집니다.

연습문제 12-7 strtok 결과 난이도 ★★☆

char s[] = "KRW,,USD, ,JPY";를 strtok(s, ",")로 나누면 토큰은 몇 개이고 각각 무엇인가요? 빈 필드를 보존하려면 어떻게 해야 하나요?

정답과 해설 보기

토큰은 4개: "KRW", "USD", " "(공백 한 칸), "JPY". 연속된 쉼표 ",,"는 하나의 구분자로 취급되어 빈 필드가 사라지고, " "는 쉼표가 아니므로 공백 한 칸짜리 토큰이 됩니다. 빈 필드를 보존하려면 strchr로 쉼표 위치를 찾아 직접 자르거나 POSIX strsep을 사용합니다. CSV 전문 처리에서 필드 개수가 달라지면 이후 모든 필드가 밀리므로 strtok은 부적합합니다.

연습문제 12-8 snprintf 반환값 난이도 ★★☆

char b[8]; int n = snprintf(b, sizeof b, "%lld원", 1234567LL); 실행 후 n과 b의 내용을 쓰세요(UTF-8 기준, '원'은 3바이트).

정답과 해설 보기

만들려던 문자열은 "1234567원" = 7 + 3 = 10바이트이므로 n = 10입니다. b에는 7바이트 + '\0'만 들어가므로 "1234567"이 저장되고 '원'은 통째로 잘립니다. 만약 경계가 한글 중간에 걸리면 UTF-8 바이트가 반쯤 잘려 깨진 글자가 남습니다. 한글이 들어가는 버퍼는 바이트 수로 넉넉히 잡고 반드시 반환값을 검사해야 합니다.

연습문제 12-9 strtoll 검증 난이도 ★★☆

12-2-9의 parse_ll에 다음을 입력하면 반환값은? (1) "-500" (2) "0x1F" (3) " 42 " (4) "" (5) "12 34"

정답과 해설 보기

(1) 0, 값 -500 — 부호를 처리합니다. 금액이라면 별도로 음수를 거부해야 합니다. (2) -3 — 10진수로 "0"까지만 읽고 'x'에서 멈춥니다. (3) 0, 값 42 — 앞 공백은 strtoll이, 뒤 공백은 우리 코드가 건너뜁니다. (4) -1 — 숫자 없음. (5) -3 — "12" 뒤 공백을 건너뛴 뒤 '3'이 남아 있습니다.

연습문제 12-10 fgets 처리 난이도 ★★☆

char buf[6]; fgets(buf, sizeof buf, stdin);에서 사용자가 "KOREA BANK↵"를 입력했습니다. buf의 내용과, 다음 fgets 호출이 읽는 내용을 쓰세요.

정답과 해설 보기

fgets는 최대 5바이트를 읽고 '\0'을 붙이므로 buf = "KOREA"('\n' 없음). 입력 버퍼에는 " BANK\n"이 남아, 다음 fgets(같은 크기)는 " BANK"를, 그다음은 "\n"을 읽습니다. buf에 '\n'이 없다는 것으로 "줄이 잘렸다"는 것을 감지하고, 남은 입력을 버리거나 오류 처리해야 합니다.

연습문제 12-11 금융 응용 — 카드번호 마스킹 난이도 ★★★

"1234-5678-9012-3456"처럼 하이픈이 있거나 없는 16자리 카드번호를 받아, 앞 6자리와 뒤 4자리만 남기고 가리는 함수를 이 장의 mask_account를 일반화하여 작성하세요(int mask_digits(const char *src, char *dst, size_t size, int head, int tail)). 결과는 "1234-56**-****-3456"입니다.

정답과 해설 보기

숫자 16개 중 순번 0~5(123456)와 12~15(3456)가 남고 6~11(789012)이 가려집니다. 노출 자릿수를 매개변수로 빼면 계좌번호(3, 4), 카드번호(6, 4), 전화번호 등 규칙이 다른 정보에 하나의 함수를 재사용할 수 있습니다.

연습문제 12-12 금융 응용 — 고정 길이 필드 채우기 난이도 ★★★

전문의 문자 필드는 "왼쪽 정렬, 남는 자리는 공백, '\0' 없음" 규칙입니다. void put_field(char *field, size_t width, const char *src)를 작성하세요. 예: width 10, "HONG" → "HONG "(공백 6개, 널 종료 없음). 원본이 더 길면 width만큼 자릅니다.

정답과 해설 보기

strcpy나 snprintf를 쓰면 '\0'이 필드 뒤의 다음 필드 첫 바이트를 덮어써 버립니다. 고정 길이 전문에서는 "문자열"이 아니라 "바이트 영역"으로 다뤄야 하므로 memset/memcpy가 정답입니다. 다만 UTF-8 한글이 width 경계에서 잘리면 깨진 바이트가 남으므로, 실무에서는 바이트 경계가 글자 중간인지 확인하는 로직을 추가합니다.
